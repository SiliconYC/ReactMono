# 06 · 交付阶段与验收

这是一份设计层面的交付路线和准入门槛，不是已经获准执行的全部 Issue，也不是开发完成报告。当前提案状态：**继续研究，首选路线已明确，等待技术/美术切片取得证据**。

## 先做什么

第一目标是经典 24 格地图的一局真实 3D 游戏：两位角色、真实规则、骰子、移动、买地、升级、收租、电脑、存档和离线。让玩家体验“走进街区做生意”，再决定是否继续扩大。

先完成一段包含转角、两类地块、三个建筑等级的代表性街景和角色演出，接着用同一套模块覆盖整个可走环线。局部样板用于校准标准；只有整张地图可操作且可结束对局，才叫纵向切片通过。展示视频、独立骰子小样或全部写死的事件都不算切片。

## 分阶段边界

| 阶段 | 交付物 | 依赖与通过条件 | 失败与回滚 |
| --- | --- | --- | --- |
| G0：迁移契约 | ESM/React 类型与打包迁移候选，资源预算对照，保留旧 UI | 现有规则/存档结果一致；同源、base、离线更新没有退步；预算变更有单独准入记录 | 回退构建变更，不动存档；不同时修经济规则 |
| G1：真实街景与资产样板 | 固定正交场景，样板角色/建筑，地图节点绑定、点击与 DOM HUD | 在真实引擎局面中选地块、识别当前角色和产权；四人站位；原生设备初测；使用生产导出链 | 最多两轮针对瓶颈迭代，仍不达标重审方向，不批量做资源 |
| G2：完整回合与一局游戏 | 演出调度、骰子、行走、购买/升级/收租、AI、保存、经典图完整对局 | [04](04-animation.md) 全部关键不变量；可玩到胜负；正常/快速/跳过等价；离线能重开/恢复 | 保留旧 UI 入口；局部禁用失败演出，规则照常；整条链不通过则切片未完成 |
| G3：覆盖原有能力 | 四角色、海港图、全部卡片/设施/金融界面与状态 | 不丢已有功能/旧档；四人本地交接、全部合法动作可达；两图正确绑定，风格统一 | 按资源包或功能切片回退，不用删功能换通过 |
| G4：正式替换验收 | 真机、真人、性能、离线更新、长局与视觉证据 | 独立测试和视觉审查通过，#73 对新候选重新执行综合验收 | 未过则保留候选状态，不关闭 #73、不启动 P5 成果计数 |

G0/G1 的技术风险与资产样板成熟后，再为 G2 等建立少量范围清楚的 Issue。不要一次把表中每个名词都变成任务；不新建一个与 #73 重复的“正式版总验收”。若后来按阶段分工，构建/存档/规则等共享文件要串行集成，禁止多个代理同时无协调修改 `app.tsx`。

## 保留和迁移测试的规则

纯规则、经济、种子、存档版本、IndexedDB、导入导出与完整对局的保障保留。现有 Node 119 项是本轮审查基线，不把固定测试数量当未来质量指标。

旧测试中存在 CSS grid 坐标、DOM 结构、UMD 文件路径、恰好六张 SVG、特定棋盘尺寸、2 MB 包体等实现约束。迁移前建立“旧断言→它保护的行为→新验证→保留旧基线”的对照；每个被替换的断言需要在相应 PR 明确说明，不能直接删除以得到绿灯。

例如，旧测试核对每个格子的 `gridColumn/Row`，新测试应核对 tileId→世界锚点→屏幕投影→点击返回同一 tileId、道路连续、产权详情正确。旧截图保留为历史对照，新画面按新标准建立视觉基线；既不能强迫 3D 保持原 CSS 坐标，也不能借迁移取消地块可达性保障。

对有争议的预算/验收调整先回写 P006 与准入结论，不擅自变更现有标准。本次文档不修改任何测试、生产依赖或 CI 门槛。

## 3D 候选资源与性能预算

**以下全部是提议值，尚未测得、尚未替代旧版门槛。** 单位 MB 为十进制，MiB 为 1,048,576 字节。原版当前实测 485,783 B，详见 [07](07-evidence-and-sources.md)。

| 项目 | 3D 候选初始门槛 | 测量方式 |
| --- | --- | --- |
| 全部运行时 JS | 未压缩总计 ≤2.5 MB | 真实 dist 全目录，含核心兼容输出与解码器；不能只报首入口 |
| 第一张地图完整离线包 | 未压缩发行字节 ≤8 MB | 含应用、角色、地图、声音、图标和全部依赖；不含 .blend 等源文件 |
| 两图完整基础发行 | 未压缩总计 ≤20 MB | 按生成 manifest 对账，不遗漏动态 chunk |
| 首局所需实际网络传输 | ≤5 MB | 冷缓存 Resource Timing/网络记录，注明 Content-Encoding；不假定 Pages 一定压缩所有资源 |
| 可操作时间 | 桌面热缓存 ≤2 s；限速冷加载 ≤8 s | 固定 10 Mbps/100 ms RTT、空缓存、同机多次，记录中位与 p95；这是目标场景，不是所有网络保证 |
| 桌面活跃画面 | 目标 60 fps，p95 帧间隔 ≤20 ms | 连续实际掷骰/行走/金币至少 60 秒；不能用静止页 RAF 代替 |
| 中档手机低档 | 目标 30 fps，p95 帧间隔 ≤40 ms | 原生手机浏览器连续 10 分钟，记录热降频、画质、分辨率和电源状态 |
| 场景规模 | 低档 ≤80k、高档 ≤150k 可见三角形 | 按实际 renderer 统计；含四角色与特效 |
| 绘制调用 | 低档 ≤120、高档 ≤200 | 计入阴影等额外 pass，不能只报主颜色 pass |
| 纹理与内存 | 纹理估算常驻 ≤64 MiB；JS heap 如可取得则目标 ≤150 MiB | 记录尺寸/格式/mipmap与资源数；heap 不是总 GPU 内存，浏览器不可得时如实标缺测 |
| 泄漏 | 连续 20 次换图/重开后资源数回到稳定平台 | 检查 geometry/texture/audio/listener、heap 趋势；不要求噪声下逐字节相同 |
| 空闲耗电行为 | 静止且无待机片段时停止连续渲染 | 记录实际提交帧；按需更新不能引入第一帧跳变 |

低/中/高档只改变 DPR 上限、阴影、装饰密度与粒子；所有权标记、路障、角色、合法操作不降级。初始 DPR 低档 1、默认最高 1.5，桌面高档最高 2；不直接使用高分屏设备的全部 DPR。

最低验证设备目标：带集成显卡的普通笔记本、6 GB 内存中档 Android、iPhone 12/13 同等级 iOS Safari；记录实际可获得的型号、系统、浏览器和 GPU。**这些是选机范围，不代表已拥有或实测这些设备。** 没有真机只可做工程候选判定，不可宣布移动端正式流畅。浏览器模拟手机尺寸不能替代手机 GPU。

## 规则与表现的自动验收

| 领域 | 必须保留的证据 |
| --- | --- |
| 核心回归 | 现有核心/迁移/保存套件；至少既有 1,000 局混合配置完整对局；非法动作、资产不变量和随机轨迹不退步 |
| 演出等价 | 相同存档与命令序列，普通/快速/关闭/随机时刻跳过最终状态完全一致；epoch/revision 一致性 |
| 路径 | 六点骰、额外步数、跨起点、整圈原位、路障、拘留、破产换人；沿实际边走，不仅检查终点 |
| 输入 | 连点/双击/触摸拖拽不重复命令；操作中读档/重开；交易表单焦点与键盘动作正确 |
| 画面 | 骰子六面、转弯姿态、四人同格、产权/抵押/等级、屋顶遮挡、两图、长中文名称 |
| 音频 | 手势解锁、静音、跳过不补播、后台暂停、所有音频源释放；无声时同样可理解结果 |
| 离线 | 冷加载→完整缓存→断网重载→整局；未下载地图提示；模型/chunk/解码器没有外链 |
| 更新 | 两个发行版本 + 多标签页；保存后更新、下载中断、配额失败、旧缓存与新缓存不混用 |
| 故障 | 缺失 GLB、加载失败、context lost、动画超时、保存失败；可恢复或导出，不锁死已存对局 |

视觉测试固定 seed、状态快照、相机、视口、画质、动画采样时刻和字体环境。记录浏览器/GPU；跨 GPU 的像素差异用容差和语义检查处理，真实断图、遮挡、错误骰面和错位不能被容差吞掉。Three 场景对象单测不能取代浏览器像素与实际交互。

## 玩家体验门槛

G2 以两名新玩家的观察性试玩发现明显问题；G4 目标至少 3～5 次实际真人试玩，与 #73 的要求一致。没有可获得的真人数据就记录缺口，不把代理截图评语称为用户研究。

给参与者的任务：找到当前角色；说明下一步能做什么；判断一块地产属于谁；掷骰后指出经过几格、发生了什么、谁收到钱；使用一张针对性卡片；完成/恢复一局。记录操作、停顿、误触和原话，尽量少引导。

首轮目标：多数参与者在 5 秒内辨认当前行动者与主要操作，在 10 秒内读懂选中地产归属/等级；正常一轮后能正确描述骰子→移动→资金结果；没有因动画等待频繁跳过或因镜头失去目标。小样本只是发现问题，不能用于声称普遍满意度。

“像游戏”的视觉评审逐项看：街区有连续道路、角色有体积/动作、建筑升级有形体差异、事件有清楚对象与反应、画面主次明确、手机能操作。全部核心项合格后再谈装饰丰富度；技术预算合格但仍像灰模工具，则继续改进，不能放行正式版。

玩法趣味另行记录：玩家是否有值得考虑的购买/升级/卡片选择、是否能理解对手造成的影响、是否愿意继续下一轮。若规则选择贫乏，应进入 P005 等玩法研究，而不是无限追加动画。

## 版本控制、发布与回滚

所有实施从 `dev` 显式创建 `codex/...` 分支，PR base 为 `dev`。每个切片有来源、范围、状态/存档兼容性、验证和回滚记录；不改 `main`。本轮只提交文档建议，不发布生产版本。

迁移期间旧 UI 是暂时回退入口，共用同一规则与保存接口；不永久维护两套完整玩法实现。新 UI 覆盖全部能力并通过 G4 后，旧复杂界面可删除，保留薄的语义棋盘作为 WebGL 故障/无障碍入口。

首轮不改存档 schema，因而回退显示层仍能读新局的规则存档。若后续确需格式升级，另立迁移切片、双向兼容或明确回退策略，再部署。新场景缓存可失效重下，IndexedDB 存档不随资源回滚清空。

公开发布仍遵守仓库授权边界：本方案不自动授权部署正式服务。正式替换必须有最新 PR/集成 CI、独立验收及按仓库流程批准的发布证据；“文档写完”“模型能转”“测试数量增加”都不是收口标准。
