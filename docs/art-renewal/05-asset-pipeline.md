# 05 · 美术生产与资源管线

## 先证明一种资产能生产，再扩大数量

首轮风险是“我们能否稳定做出好看的角色、街区和动作”，不只是渲染器能否画立方体。投入顺序是完成样板角色→完整回合→代表性街景→复制到一张地图→更多角色和主题。样板不合格就改造型和管线，不靠批量资源遮盖问题。

Blender 用于可编辑模型、绑定和动作；GLB 用于发布。可用脚本生成道路、地基、窗户、屋顶组合和批量导出，但角色比例、建筑层次、构图、动画重心仍需实际画面审查。AI 出图可以做探索参考，不能把单张概念图当成完整多视角模型或可发布资产。

glTF 2.0 支持场景、材质、网格、骨骼与动画，适合作为交付边界；不依赖某个运行时私有模型格式。[Khronos 规格](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html)、[Blender 支持的交换格式](https://www.blender.org/features/pipeline/)

## 首切片与正式覆盖的资产清单

| 类别 | 首个可玩切片 | 扩展到完整替换时 | 复用方式 |
| --- | --- | --- | --- |
| 角色 | 狐/熊两种轮廓，1 套兼容骨架 | 四种可辨角色；多人同形也有号码/配色 | 骨架与动作共享，头部/配件/比例独立 |
| 动作 | idle、walk、roll、happy、hurt；终局先复用反应 | 独立胜利/失败、设施状态反应 | 原地动作、根节点走路径，不按方向导出 |
| 骰子 | 1 枚六面骰、六面映射、六种终点轨迹 | 同一骰子继续使用 | 共用几何和材质，不为结果复制整套模型 |
| 道路 | 直线、转角、节点标记、起点、路缘 | 海港材质/地面套件 | 旋转与实例化；转角连续，tile 对应可见 |
| 普通地产 | 1 套空地 + 0/1/2 级建筑 | 2～3 个建筑家族各三个等级 | 共享墙/屋顶/窗模块；每次升级改轮廓 |
| 特殊节点 | 机会、卡片、休息标记 | 医院、监狱、商店各 1 个辨识模型 | 第一切片若未做专属模型，仍须标清真实类型与合法交互 |
| 街区环境 | 2 种树、路灯、长椅、1 个中心地标 | 海港码头/仓库/水面等少量主题物 | 共同色板和实例批次；环境不能遮住路径 |
| 规则标记 | 产权旗、抵押牌、路障、选中地界 | 覆盖所有现有规则状态 | 以规则投影驱动，不烘死在建筑材质里 |
| UI | 玩家头像、卡片图标、动作按钮/资金标识 | 同一风格覆盖全部面板 | 头像可从生产角色固定相机渲染，再做尺寸适配 |
| VFX | 金币短流、落地尘、建造短效果 | 少量事件专属效果 | 共用粒子池，限制寿命与数量 |
| 音频 | 骰子/脚步/钱/建造/警示 5 类短音效 | 胜负、卡片与设施提示 | 先复用现有原创合成能力，后续独立打磨 |

切片中单一建筑家族是验证范围，不等于正式地图允许全是同一房子。完整替换前必须覆盖两图、四人和全部已有规则的可理解表现；首切片不足部分如实标注。

## 模型交付规格

以下是初始制作上限，最终以画面与 [性能门槛](06-delivery-and-acceptance.md) 双重检验。

| 资源 | 初始建议 | 约束 |
| --- | --- | --- |
| 单角色 | 1,500～3,000 三角形，骨骼 ≤24，材质 1～2 | 常驻 4 人；投影到手机后仍有清楚轮廓 |
| 单普通建筑 | 600～3,000 三角形，材质 ≤2 | 高级楼也要控制高度；升级件优先复用 |
| 树/路灯等道具 | 100～600 三角形，材质 1 | 同类实例化；少量有意变化避免机械重复 |
| 骰子 | ≤1,000 三角形 | 倒角与点数清楚；不用高细分球化骰子 |
| 纹理 | 优先 256/512 色板；常规上限 1,024 | 不透明优先；禁止每个小道具一张 2K 贴图 |
| VFX | 同屏最多 64 个短寿命粒子 | 无 VFX 时零持续更新；关闭动效时不生成 |

三角形数按导出后三角化结果计，不按 Blender 面数计。材质变体、阴影 pass 和骨骼都会增加真实开销，不能只报“低多边形”就忽略 draw calls。

### 坐标与命名

- 发布坐标统一 Y 向上、地面 X/Z；模型正面沿 +Z。Blender 源文件可保持其工作坐标，但导出预设必须自动转换并在预览中验证，禁止各资源人工猜轴。
- 角色 pivot 在脚底中心，建筑 pivot 在占地中心，地面高度为 Y=0。1 世界单位对应一个道路节点间距；导出模型 scale 应为 1，不靠运行时负缩放镜像角色。
- 角色标记 `root`、`pelvis`、`spine`、`head`、左右肢体，配件插槽 `hand_r`、`head_top`；同骨架角色用同一命名和静止姿态。
- clip 命名固定 `idle/walk/roll/happy/hurt/win/defeat`；只要求当前阶段清单中的 clip，缺失时回落姿态可解释且不可锁死播放。
- 建筑节点分 `base/body/roof/sign/owner_anchor`；屋顶能单独隐藏以处理遮挡。包内节点名不得因一次重导出随机改变。
- Blender 约束、驱动器、复杂材质不假定能在浏览器自动运行。导出后检查实际 clip、法线、色板、包围盒、阴影和纹理；必要时烘焙为支持的形态。

## 资源目录与清单

源资产按 `assets-source/{characters,buildings,props,audio}/` 保存可编辑文件、导出设置和作者记录。导出产物归 `public/assets/` 或由构建 import 管理，最终使用内容哈希 URL。源文件、检验截图和大体积工作缓存不混入 PWA 包。

资源 manifest 至少包含：稳定 assetId、内容版本、导出文件、内容哈希、字节数、依赖、三角形/材质/纹理统计、动画列表、pivot/单位/包围盒、用途、来源和许可证据。场景用 assetId 引用，不把手写文件名散在组件中。

规则地图版本、视觉场景版本、资源包版本和发行 releaseId 是不同字段。只改屋顶颜色不升级 GameState.schemaVersion；地图路线规则变化则不能只换 sceneVersion 逃避存档迁移。

首轮优先低纹理、简单 GLB，避免为几个小模型提前加入多种压缩器。达到实测瓶颈后再比较 Meshopt/Draco 或 KTX2：包括网络减少、解码耗时和内存峰值。若启用，JS/WASM 解码器必须同源打包、版本固定、PWA 完整缓存；小文件不一定值得付出新解码器成本。

## 每项资产的生产闭环

1. **灰模验轮廓**：在正式相机和目标字号/角色尺寸下看，不只看 Blender 大视窗。确保当前角色与房屋可分离。
2. **定色板与灯光**：同一场景测试明暗、产权色、选中边线和手机缩小，不接受单个资产漂亮但整体不一致。
3. **动作/升级**：角色走转角、抛骰、收租反应；房子由空地到三个产权等级。验证动作的中间帧和遮挡。
4. **导出验证**：资产存在、哈希正确、无外链、包围盒/轴/pivot/材质/clip 合规；失败不进入正式包。
5. **浏览器集成**：同图四人、近远两侧、建筑遮挡、快速模式、低画质、重载/换图和离线。
6. **复用实验**：第二个角色/建筑家族用同管线完成，记录返工点。只有第二次也能稳定产出，才宣称管线可扩展。

资产检验场是开发工具，展示生产资源、固定镜头、动作按钮、产权/抵押/遮挡状态及统计。能绕资产看一圈不等于主游戏提供自由镜头。正式验收仍在真实对局内完成。

## 版权、成本与可回退性

使用原创或明确允许当前用途的资源。清单记录作者、来源链接、许可证全文/证据、修改方式和署名需求；“AI 生成”“网上免费下载”或“由代理制作”都不自动等于 CC0。未经授权不使用《大富翁4》或 Crossy Road 的角色、贴图、音乐和商标图形。

本轮不购买资产、不开通服务。产能应记录样板角色建模/绑定/动画/导出各阶段耗时、修改次数，以及新增第二个角色的成本；数据取得前不承诺几天完成或给出虚构人日。先减少材质、骨架类型和建筑家族数量，再考虑压缩细节。

若 3D 切片经两次针对性优化仍未达到设备或画面门槛，停止量产。在同一套已做好的模型上测试八方向预渲染，或回到 2D 风格评审。这个退路能复用源模型；不为“将来可能切换”从第一天维护两套正式渲染器。
