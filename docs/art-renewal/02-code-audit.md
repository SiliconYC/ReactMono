# 02 · 现有代码资产取舍

审查对象：`dev@a560589`，与 2026-10-17 查询到的远端 `dev` 一致。以下判断是模块级取舍，不是逐行正式代码审计。文件链接相对于本文；原始运行证据见 [07](07-evidence-and-sources.md)。

## 有价值，但不足以代表正式游戏

119 项现有 Node 测试通过，包含确定性规则、模拟、存档和发行检查。当前版本能真正开始游戏、投骰、购买与结束对局；已经有银行、股票、贷款、卡片、设施、多地图和电脑策略。因此“完全没用的演示”并不准确。

用户指出的产品落差则成立：当前游戏的主要表达仍是格子、头像、按钮、数值和日志。测试能证明资金与状态正确，不能证明街区有吸引力、角色有生命感、回合值得观看。增加通过的测试数量不会自行补齐这些品质。

## 需要特别处理的接口事实

1. **事件已有基础。** `ActionResult.events` 是本次命令事件，不必从 `state.events` 全量历史猜差分。`GameEvent.details` 目前是松散的字符串/数字字典，演出侧先做类型化归一化和校验。
2. **移动路径尚不完整。** [turns.ts](../../src/core/turns.ts) 的 `player_moved` 只写 `from/to`；但同批 `die_rolled` 有 `value/bonus`，路障事件有 `tileId`。当前单环可恢复实际步数与路线；恢复失败应直接同步终态并记录原因，不播一条编造的路径。
3. **一次投骰已经结算多个结果。** 费用、强制清算、破产甚至当前行动者改变，可能在同一次 `applyAction` 完成。不能只让角色慢慢走、同时把 HUD 提前切到下一个人。
4. **地图校验是严格的。** `validateMap` 注册且比对现有地图坐标/路线。新视觉布局放在外部 `SceneDefinition`，不能把世界坐标写回旧存档试图绕过校验。
5. **事件并非完整事件溯源协议。** 现有事件不保证能还原每个中间经济快照。新表现层用命令前后投影控制揭示，不把事件列表当成可重演经济账本。
6. **历史增长是独立风险。** `state.events` 持续累积，导入还有 4,000,000 字符上限。演出队列只保留当前命令并及时释放引用；后续用长局数据决定是否另立事件归档提案，本轮不改存档格式。

## 不要让旧资产成为约束

“保留引擎”不表示冻结未来玩法。首轮 3D 切片先沿用真实规则，以隔离美术与交互成本。后续若要岔路、交通工具、人物能力或更强对抗，应作为独立可验收的规则变更开展；更换规则时继续维护迁移、重放和经济不变量。

现有地图都为环线，这只能支撑第一轮表现重建，不能作为经典玩法深度已经足够的证明。新模型也不能掩盖当前事件选择少、人物能力尚未形成和长局趣味待验证的问题。
