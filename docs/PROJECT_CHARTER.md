# 项目目标与产品验收边界

## 北极星目标

交付一款受到《大富翁4》启发的高完成度浏览器经营棋盘游戏，并在真实开发过程中尽可能验证 AI 自主定向进化能否长期有效。

**产品完成是硬约束；自主程度是第二维度，不是替代品。** 不能为了展示“AI 很忙”而牺牲实际可玩性、可靠性、体验或维护成本。

## 初期的可玩闭环

首个闭环应能由玩家从新建游戏持续玩到正常结束，至少具备：

- 一张可走通的棋盘、玩家初始资金、回合次序、骰子与位置推进。
- 可执行且账目正确的地产购买、过路费结算及资金变化。
- 基础电脑玩家，或足以独立完成一局的明确本地多人控制机制。
- 破产、剩余玩家胜出或其他明确定义且实际可触发的胜负条件。
- 界面显示当前局面及合法操作；任何关键一步不能依赖开发者手动改状态。
- 覆盖关键规则的可重复自动测试，以及至少一次真实完整对局的验证记录。

首个闭环不要求完整股市、全部人物、全部卡片或原版美术。先证明真实可玩，再扩展复杂系统。

## 后续系统

地产与建筑、随机事件、卡片/道具、股票与经济系统、电脑对手策略、多地图、人物差异、音画表现、存读档与浏览器部署，均由自主规划逐步纳入。

不要机械照抄原版各元素；首先保证机制可解释、可测试、平衡且好玩。对原版受保护的美术、角色形象、音频或文本，须使用获得授权的素材或原创替代，并避免暗示与权利人存在授权关系。

## 核心工程约束

- **规则核心脱离界面**：游戏状态只经明确的事件/命令变更，便于测试与重播。
- **确定性和可观测性**：支持设定随机种子、记录游戏事件、快速模拟对局；后续为浏览器测试提供必要的可观测接口。
- **兼容存档**：提前定义带版本号的存档数据结构；重大格式变化需要迁移策略或清晰的不兼容提示。
- **自动化质量保证**：规则单测、大量模拟、浏览器端到端测试和视觉回归互补，不能互相替代。
- **以用户价值排序**：稳定可玩、可完成一局、关键缺陷修复优先于锦上添花。
- **独立验收**：实施者不能只凭自述或自行放宽测试标准宣布完成。

## 成功如何评估

产品维度：实际完成对局、核心规则正确率、阻断性缺陷数、存读档可靠性、体验和性能。

自主开发维度：AI 自主发现并提交的有效 Issue 比例、独立验收通过率、回归发生率、成功交付的功能、每次改进耗费、人工干预次数及改进是否持续收敛。

不能用提交次数、代码行数、Issue 总量、Token 消耗或者主观自夸代替成功。
