## 验收分界与改进门槛

- **阻断门槛**：P1～P3 `npm test` 全绿；原浏览器脚本包含多人、多地图、银行、贷款、股票、卡片、存档、旧存档迁移、PWA 离线；P4 不允许降低覆盖率或改变交易状态机。出现非法动作、资产对账变化、水平溢出或离线失败视为阻断。
- **响应式基线**：同脚本固定 6 组尺寸、地图和人数，`measurements.json` 做版本对照；目标 320/390px 无横溢，触摸优先操作至少 44px 高，关键文字可读。开发前指标用本次原始 JSON，而非凭空估算像素。
- **性能基线**：记录同源导航用时、浏览器中一次两轮整局的操作次数及耗时；CI 共享虚拟机的时间不是最终手机真实帧率。将来保持相同种子、浏览器、尺寸重复测量，须说明机器差异，不能把波动解释为提升。
- **数据与真人反馈**：上述 1,000 局只支撑规则正确性/行动量描述；当前无招募真人样本、问卷或观察记录，主观易用性与趣味**待真人验证**，不得标注“已玩家证实”。
- **#63 设计约束**：先建立两种方案并选一种，保留主要棋盘和主行动对比优先级；可点击的 React 样例不能替代真实经济操作；只用原创 CSS/矢量几何，所有文件纳入同源 PWA 缓存。
