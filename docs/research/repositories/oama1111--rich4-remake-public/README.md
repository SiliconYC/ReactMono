## 2. 产品定位与原作关系

上游标题写“《大富翁4 高清重制版》”，README 明确目标是 **《大富翁4 超时空之旅》v3.11（2001）** 的跨平台重制，而不是独立证明对 **1998 年原始基础版** 的规则完全一致。它有意朝原作规则、数值与交互还原；另增 WebSocket 大厅、托管、多端包装、高清素材管线等非原作功能。（C，E15、E17）

本项目研究区称其“以忠实重建为产品意图”的候选，而非真正证明百分之百忠实。尤其 **原版重建与“受大富翁启发的现代原创视觉产品”是两套标准**。ReactMono 目前以 3D 原创棋盘、React/Three.js、离线 PWA、简体中文单机为核心，不应该因它的 2D 原版表现方向而倒退。

源码血缘的**可证/不可证**：
- Github 元数据 `fork:false`，所以不是平台记录的 `mytbk/rich4` fork；`mytbk/rich4` 独立 GitHub 项目存在且主要是汇编逆向材料。
- 本上游 `README.md:53–59` **明确致谢** mytbk/rich4 与 Codeberg 的 `rich4_asm`，称项目可行性依赖逆向工作（C，E15）。`state/types.ts:27–31` 引用 `rich4-re/asm` 中的结构，`data/source-fidelity.test.ts` 解析外部反汇编 C 表比对（B，E11），证明了研究方法层面的实际依赖。
- 并无权限检查其私有原库或进行完整相似度/提交祖先比较，不能由“致谢/许可证相同”直接推断整套 TypeScript 代码复制自 mytbk，也不能宣称完整独立创作。此处保留明确的**血缘未决项**。（E15、E16）

## 3. 代码架构与数据流

```text
合法原版安装目录（公开镜像之外）
      → packages/assets-pipeline：MKF/FLIC/GND 解包、manifest
      → 浏览器 /assets/game/* 或桌面 rich4://localhost/*
packages/data 数值表、地图/存档解析
      → packages/core：纯状态 + Action + reducer + RNG + AI + 事件/经济
      → packages/client：UI/动画/声音、用户决策、宿主/存档接口
                               ├─ 单机：本地 reducer（浏览器 localStorage）
                               └─ 联机：NetClient.intent → WebSocket /ws
                                       → packages/server RoomHub/Room
                                       → 检查合法性、服务端 reducer 镜像
                                       → Sequencer 编号广播 → 客户端重放
packages/desktop：Tauri Rust 外壳、资源 URI/本地文件/存档
```

- **规则引擎**：`packages/core/src/state/actions.ts` 声明合法意图；`state/reduce.ts` 将固定地图拓扑作为只读输入，对 `GameState` 生成新状态。`MapTopology` 与实时土地归属分离。核心入口另有 AI 政策、银行、股票、卡片、特殊事件、随机数策略。（B，E01–E03）
- **持久化**：`loaders/savegame.ts` 是版本化 JSON 与原版二进制“只读导入”两路；浏览器 `host.ts` 回退到 `localStorage`，不是 ReactMono 的 IndexedDB 多存档设计。（B，E08、E12）
- **联机**：服务端 **不是无状态广播器**。尽管 `net/sequencer.ts` 顶部评论曾写“不跑游戏规则”，实际 `server/room.ts` 保存 `#mirror`，在提交前执行 `reduce()`，失败拒绝，在成功后维护 `stateFingerprint`。这是源码内部文字与现状的显著不一致（B，E05–E07），以调用链为准。它也承认私人对局不能防恶意客户端作弊。（E05）
- **原生端**：`desktop/src-tauri/src/lib.rs` 将大体积 MKF 异步经 `rich4://` URI 交给前端，不经 JSON IPC；公开的 `tauri.conf.json` 不含 `bundle.resources`。编译成功的桌面包仍须用户自备合法原版资源。（B，E09、E20）
- **测试与运行**：`package.json` 提供 `pnpm typecheck/lint/test/check`；`replay.test.ts` 写明 1000 次同种子指纹和录制/分段重放；`vitest.config.ts` 配 `RICH4_WORKSPACE`，真值测试没有外部 `rich4-re` 直接 `describe.skip`。镜像的 CI 无素材通过不能证明保真。（B，E03、E11、E13）
- **维护代价**：虽然包划分较清晰，`reduce.ts` 约 **10,935 行**、`client/main.ts` 约 **13,913 行**，聚合文件过大，是实践参考时不应照搬的地方（B，固定 SHA 文件长度可复核）。

## 5. 核心源码调查与原版证据

**发现 A — 确定性引擎设计（B，E01–E03）**：
- [Action 和种子输入](https://github.com/oama1111/rich4-remake-public/blob/42ad97ad31f07541a9af35415e36be4da4147484/packages/core/src/state/actions.ts#L16-L35)；[纯函数约定](https://github.com/oama1111/rich4-remake-public/blob/42ad97ad31f07541a9af35415e36be4da4147484/packages/core/src/state/reduce.ts#L1-L10)；`reduce.ts:1602` 归约，`:6996` 重放。
- **实义**：顺序相同的动作应得到可对比状态；该断言与测试代码实实在在存在（`replay.test.ts:28–112`）；**但本次不能给出运行通过率**。
- **原作来源等级**：确定性重放是重制版架构选择，不应冒充来自原版反汇编。

**发现 B — 原版随机数与更真实的可重复性之间的冲突（B，E02）**：
- `rng/policy.ts:43–61`：单机策略不保存随机状态、会在新局/读档后/推进回合重播种；联机仅开局播种并保存种子状态。确定性回放需要宿主把播种写成 `reseed` 动作。
- **ReactMono 应学**：只复制“所有非确定性输入显式记日志”的原则；其单机模仿旧版随机再播种政策没有必要照搬，会降低我们固定种子回归的可重复性。

**发现 C — 拍卖不是回合主人独占提交权（B，E04–E06）**：
- [actingSeat](https://github.com/oama1111/rich4-remake-public/blob/42ad97ad31f07541a9af35415e36be4da4147484/packages/core/src/net/acting-seat.ts#L27-L41) 将当前响应者判断为被动卡持有人或拍卖出价者；`Room` 使用它，而不是 `currentPlayer` 判合法性（`room.ts:120–146`）。
- 它在作者 `net-20260919.md:62–110` 中对应一个四座死锁复盘（C），属于**具体可复用的“交互归属”设计教训**；不要借此认定我们需要联机服务器。

**发现 D — 服务端镜像覆盖了旧注释所说的“只定序不跑规则”（B，E05–E07）**：
- `sequencer.ts:1–15` 简述“服务器不跑规则”，但实际 `room.ts:224–254` 的回调 **先执行 reduce 检查，再分配序号**；可以拦截非法回合和恶意 `rollDice.forced`。
- 需要同时读真实调用路径才能判断。尽管服务端有镜像和非法动作闸门，**源注释也提醒这不等于严格安全的反作弊认证**；不要为 ReactMono 引入新后端或账户。

**发现 E — 保真测试中的“可跳过真值”陷阱（B，E10、E11、E13；C，E18）**：
- `data/source-fidelity.test.ts:1–16` 明写 `hasSource ? describe : describe.skip`，外部 `rich4-re` 缺失即跳过卡片/道具数值对照；资产解包依赖本地 MKF；CI 自承镜像不含资源。
- 上游六区溯源台账举原版 EXE VA、部分 `approx` 和 `follow-up`，是有价值的**待复核索引**而非我们独立证明。任何从具体 VA 到玩法规则的迁移，应先用另行合法取得的原始材料独立复核，再在 ReactMono 实现自己规则测试。

## 6. 对 ReactMono 的学习/排除建议

| 优先级 | 方案与可复现验收路线 | 价值 | 成本/兼容性 |
| --- | --- | --- | --- |
| 1 · 学习 | 为目前的规则事件维护**动作录制 → 固定种子/状态回放 → 指纹一致**的更强测试；覆盖出牌、股市、破产、跨天。复核失败应打印第一条分叉动作。（E01–E03） | 高：可定位 AI/存档回归 | 中；完全本地，兼容无后端 |
| 2 · 学习 | 引入“**谁是当前交互决策者**”纯规则查询，明确拍卖、被动卡或多人交接的合法提交者；补两角色竞价的死锁回归。（E04、E17） | 高：避免交互与玩家回合混淆 | 低/中；不需要联机 |
| 3 · 学习 | 对数值和规则建立**来源台账**：原版实测 / 反汇编锚点 / 文档 / 现代玩法选择各自标记；将未知留为未知，禁止凭作者台账直接宣告一致。（E11、E18） | 高：减少伪“原版保真” | 中；先针对争议数值 |

## 7. 缺口、风险和证据矛盾

1. **公开镜像 ≠ 完整复刻可下载可玩**：没有 `assets/game`、原版 EXE、音源/贴图；`filter-repo` 删除历史是作者说明，不能独立证明所有派生资源均有清晰授权。（E16、E20、E21）
2. **工作流 CI 的“通过”有真值覆盖缺口**：`RICH4_WORKSPACE` 外部目录缺失，测试直接跳过；公开仓库用例全绿并不验证原版数据一致。（E11、E13、E16）
3. **源码与旧注释不一致**：`Sequencer` 顶部否认服务端跑规则，而 `Room` 的 reducer 镜像真实存在。应以调用链为准。（E05、E06）
4. **上游验收的历史性**：报告中可能有过时端点（`net-20260919.md` 前言记 `/ws` 迁移）、私人源库 Issue、旧提交和未推送分支记录；不能无条件迁移到固定镜像提交。（E17、E16）
5. **原作版本混淆**：v3.11/2001 的作者定位不能覆盖 1998 原始版本；某些逆向注释和表结构可能跨版本，必须明列来源与版本。（E15）
6. **许可证与商业素材分离**：GPL-3.0-or-later 只描述受许可代码；原版商业数据、标志、音乐和角色没有据此变成自由素材。即使不直接带文件，用户自行导入亦涉及合法来源与分发设计；本次不移植。（E14、E20）
7. **画面未能验证**：README 的 DOM 面板截图不是本研究的实测游戏画面，也不能凭代码行数/单测数评分美术。源代码并没有消除在 ReactMono 追求商业级 3D 视觉的必要。（E20）

## 9. 结论与下一步

**结论：`read_only_reference`**。从确定性动作归约、重播种语义、决策权归属、回放/指纹、带证据的数值出处和存档版本化中学习，但不复制 GPL 源文件、不改变 ReactMono 的纯静态离线产品约束、不导入原版受保护美术音频，亦不把原版商业素材缺失当作“源码完全没有此功能”。

尚待解决：原版 v3.11/1998 差异；上游作者声称的 EXE VA 可否用合法样本复核；各台账 `approx/follow-up` 残项；公开镜像跳过的真值测试数；Windows/Linux/WebKit 和真人完整终局实测；mytbk 具体复制血缘。优先由 **综合研究 #104** 跨仓库核对，不急于开新重复 Issue。

**交付与验证说明**：本目录的 [源码索引](source-index.md) 含固定 SHA 与定位、[结构化证据](evidence.json) 含 21 条分级证据及 14 项功能状态；本轮没有对上游运行 `pnpm check`、浏览器或 Tauri，因此没有造测试截图，也不宣称验证原版忠实度。研究本身仅修改 `docs/research/`，未改 `src/`、`demo3d/`、依赖或 `main`。
