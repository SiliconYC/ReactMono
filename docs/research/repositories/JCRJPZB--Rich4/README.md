## 2. 产品目标及与原作的关系

仓库描述为“大富翁4复刻”，`Game.js` 固定“Japan”和阿土伯、沙隆巴斯、钱夫人、孙小美，配置包括点券、魔法屋、股票、地产、卡片。它显然追求原作的主要玩法氛围，而非一个纯原创通用 Monopoly 游戏（R05/R06）。

**不等于 1998 原版等价复刻**：本项目没有可验证的原版反汇编、资产来源台账、规则对照用例、版本说明或整局重演。本报告以**2021 年作者 Cocos 原型**定位；无证据证明财务参数、卡片效果、事件概率与原版相同。与 2024–2026 年其他 Rich4 项目的代码血缘也没有直接提交祖先关系证据；相同主题/角色不等于代码复制。结论为“原版启发的衍生复刻尝试”（R01/R05/R14）。

## 3. 代码架构与数据流

- **启动**：`assets/Script/GameCore/Game.js` 的 `onLoad` 用固定 `cc.find(...).getComponent(...)` 定位地图、人物、股票、卡片、小地图。接收 `MapReady / PlayerReady / UIReady` 三个事件后进入 `gameStart`；地图/角色完全硬编码。未见可选择新游戏参数的启动界面路径（R05）。
- **资源/场景**：`ResourcesMgr.js` 包装 `cc.resources.load`；`Game.fire` 是 Cocos 序列化场景而非浏览器可独立打开的游戏。渲染强耦合 Cocos 节点、精灵、Prefab、Atlas、镜头；它不是 Three.js 工程，也没有原生 React/PWA 入口（R02/R03）。
- **地图数据**：`Map.js` 加载 `/config/Japan`，生成背景、路与建筑；`PointMgr.js` 将 `point/line/reverseLine/path/reversePath` 写入有向行走图。单份 `Japan.json` 定义 96 个点、3 组路线段、15 条道路与 2 个建筑记录，另含股票数据。岔路列出候选但玩家控制层目前默认选第一个（R06/R07）。
- **回合与经济**：`PlayerRound.js` 轮流授予控制权，掷骰（`DiceControler.js`）后调用 `PlayerCtrlDirector.move`，停留点转到 `PlayerLandActivity`。土地购买、租金流转和升级直接操作玩家属性、地图精灵；现金/存款/股票在 `PlayerAttrDirector` 汇总，逻辑和显示**没有纯数据隔离**（R08/R09）。
- **辅助系统**：`BankPane` 处理存取款；`StockMgr` 包含股票价格涨跌及交易面板；`CardMgr` 包含卡片管理和事件；`ToolMgr` 的主体业务几乎全是注释（R10/R11）。
- **测试/存档**：`assets/Script/Test/*.ts` 属于 Cocos 场景测试/动画试验，没有在树中确认独立规则测试框架、断言、CI、游戏状态序列化/恢复链路或正式打包产物；不得据此绝对声称“整个程序没有存档能力”，只标“公开源码未确认”（R12/R15）。

### 本次独立静态数据核查（等级 A，非游戏运行）

研究者通过连接器读取固定 SHA 的 `Japan.json`、`Game.fire` 和 `TestScene.fire`，在 V8 中直接 `JSON.parse`：三者解析成功，场景分别含 707 与 31 个序列化记录。节点 96/96、路段 3/3、路径 3/3、道路 15/15、建筑 2/2，路线与路径索引越界 0。此项**只检查 JSON 可读性及索引范围**；没有验证场景依赖 UUID、Prefab 绑定、动画、素材授权、逻辑启动或完整对局（R04）。

## 5. 五个关键技术深挖与源码级反证

1. **事件门闩不等于可运行**：`Game.modelLoaded` 等待三类 Ready 事件后调用 `gameStart`，`gameOver` 仅打印日志且结果界面明确“待编辑”；树存在 `Game.fire` 只能作为场景资产证据（R05）。
2. **数据驱动地图与非完整岔路控制**：`PointMgr.init` 读取路线图和反向线路，`findNextPoint` 可能返回多个相邻候选；`PlayerCtrlDirector.moveToNext` 却强制 `next[0]`，注释承认“还没有实现”。这不是支持岔路玩家抉择的完整产品（R06/R07）。
3. **经济有功能但无严格不变量**：`PlayerLandActivity.buyLand` 扣款与买地配套，而 `upgradeLand` 只调用加级和提示，**不扣款**；`PointMgr.buildFacility/changeFacilityLv` 使用 `this.point` 而非局部 `point`；`PlayerAttrDirector.getPlayerMoney` 以 `==` 替代赋值维护 Total。这些是静态可见缺陷，具体运行后果尚未用引擎验证（R09/R10）。
4. **AI 的“有脚本”不等于会下棋**：`PlayerRound.init` 初始化 `isBot={}` 后立即读 `getPlayerBot`，导致未能从 `PlayerAttrDirector.isPlayerBot` 取得配置；`PlayerAttr.js` 还把 `isBot=false` 作为初值。并且 `this.aiCtrl.init(playerNames, players, playerAttrDire, playerCtrlDire)` 与 AI 的单参数 `init(playerAttrDire)` 不吻合；事件监听仅在抽中有牌条件时触发路径，没有普遍完成回调，交易逻辑存在先用 `stock` 后声明与未定义 `vlo`。不能声称完成可操作电脑对手（R08/R13）。
5. **“卡片已写”≠ 道具、动画、完整特殊设施已写**：`CardMgr` 确实有卡片事件路由和买卖，`ToolMgr` 的内容大量整块注释，`PlayerLandActivity.randomEvent` 直接跳过道具事件；`Magic.js` 明列尚未完成的命运牌、住院和道具变卖（R11）。

## 6. 对 ReactMono 的五项建议（不移植代码）

按玩家价值/实现成本/技术适配性排序，所有建议都要在 **ReactMono 现有引擎**内部单独评审，不导入 Cocos 素材：

| 优先级 | 可借鉴或排除事项 | 价值 / 成本 / 适配 | 具体可复核路线 |
| --- | --- | --- | --- |
| 1 | **借鉴有向线路＋反向路线拓扑的思想**，不抄代码 | 高 / 低–中 / 高 | 以 ReactMono 地图 JSON 的节点/边为输入做交叉口、多路线、反向走和路径闭环的无头测试，对照 S2 的数据表达 |
| 2 | **借鉴启动依赖门闩的可观测性**，不沿用全局字符串事件 | 中 / 低 / 高 | 用现有 ReactMono 模块加载状态加入超时、失败可见、未就绪禁止首回合的单测；参考 S1 的 Ready 分类 |
| 3 | **纳入产权/余额不变量反例**，直接排除其实现 | 高 / 低 / 高 | 对现有规则写“升级必须扣除指定成本、交易前后总资产守恒、无主地产不得收费、设施升级由局部实体决定”的回归用例 |
| 4 | **纳入 AI 命令活性反例**，不复用其 AI 模块 | 高 / 中 / 高 | 无头模拟中要求每个合法 AI 回合可结束；测空牌、空股票、交易失败、跳过回合、分岔；拒绝长期挂起的回调式控制 |
| 5 | **排除 Cocos 场景、静态美术和强绑节点 UI** | 高风险规避 / 低 / 高 | 保持 TypeScript 核心规则独立、Three.js 原创 low-poly 视觉、Pages/PWA；仅从静态代码提取问题清单，不复制 `.fire` 或图片 |

上列是**研究建议**而非本 Issue 已改进产品的声明；任何后续研发需单独验收，不能让这个低成熟度项目反向降低现有 ReactMono 产品标准。

## 7. 缺口、风险、冲突与可运行性

- **运行缺口**：可确认需要 Cocos Creator **2.4.3** 时代工程导入；Git 树有 `assets/`、`settings/`、`project.json`，但没有独立 `package.json`、构建入口或 Release。通过仓库 API 拿到文件，而本地 `git ls-remote https://github.com/JCRJPZB/Rich4.git HEAD` 返回 `Could not resolve host: github.com`；未装 Cocos 编辑器，也不能确认机器上的完整预览/打包可用。需要后续能联网的隔离环境安装匹配版本，从 `Game.fire` 运行并录屏，再证明操作闭环。**不能把“JSON 可解析”升级为“游戏能玩”**（R03/R04/R12）。
- **可复现性**：没有可定位的 CI/脚本测试体系；`Test.ts` 仅手动场景组件，与运行命令无关。随机数直接调用 `Math.random`，没有可见的重放种子约束；同样不能声称不存在隐式引擎测试（R07/R12）。
- **真实体验**：无独立浏览器/手机截图、按键实测、帧率、完整一局、断线恢复、玩家反馈。视觉品质和互动感尚不能可靠打分（R03）。
- **许可与素材**：无声明源码授权/素材授权；截图、音频、人物、字体及“原版”商标使用可能存在独立风险。原创/授权证明未知；对 ReactMono 的可操作策略仅限思想学习与独立实现（R15）。
- **模块边界与质量**：大量字符串路径的组件直接耦合；方法参数错配、未定义变量、未扣款、道具整块注释与 README 缺失降低长期维护性（R05/R09/R11/R13）。
- **血缘问题**：GitHub `fork=false` 和单父为空的初始提交只说明该仓库 Git 图上没有可追踪祖先；与后来 `rich4-re` 或 `rich4-renew-app` 等项目的代码共同来源**未核实**，不能凭仓库名称、引擎差异断言“完全无关”（R01/R14）。

## 9. 结论、未解问题与后续行动

**决策：`read_only_reference`（只读研究）**，不作为 ReactMono 的游戏源代码、贴图、人物造型、玩法参数或成熟视觉设计的移植来源。相较当前已具多人、无头模拟、存档/PWA 与 Three.js 的 ReactMono，这份 2021 年 Cocos 原型的价值主要是：反面检查清单、早期图结构思路、事件驱动启动机制（R05–R15）。

开放问题（未阻碍本轮静态研究的交付）：① 用 Cocos Creator 2.4.3 打开 `Game.fire` 的真实启动、输入与完整局；② 场景 Prefab/图集全部引用及来源授权；③ 与其他项目是否存在代码文件级血缘；④ 存档、声音、设备打包是否在未追踪文件/历史资产中出现；⑤ 原版完整规则/数值是否有权威对照材料（R03/R12/R14/R15）。

如确有后续资源，优先开**隔离的 Cocos 2.4.3 可启动性与版权来源专项调查**；否则不增加对 ReactMono 核心产品的开发依赖。记录表中未能验证的结论不会升级为“已完成”，也不会用本报告替代玩家级验收。
