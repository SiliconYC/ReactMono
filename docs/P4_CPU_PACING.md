# P4 #70 · 电脑回合节奏、主动快进与可复现验收

- **始终使用原规则引擎**：每一条电脑动作仍由 `chooseComputerAction → applyAction` 产生，不直接修改资金、骰子、回合或随机种子。快速与正常仅控制前端 `setTimeout` 间隔；`src/ui/computer-pace.ts` 是无状态纯呈现工具。
- **计时基准（修改前）**：#69 正常模式每条电脑命令统一等待 220ms，快速模式 8ms；CPU 计算与等待未单独记录。#62 对等待主观结论保留为未证实体验假设；#45 的 1000 局统计是引擎测试，非真人等待时间。
- **现在**：正常情况下仅引导动作 115ms、掷骰/停留 200ms、卡片/购地 170ms；收租、入院、破产等后续展示延长为 245ms，避免迅速跳过关键结算。快进保留 8ms。快捷键位于电脑当前行动区，可随时「暂停电脑／继续电脑」、「快进电脑／恢复正常速度」，不占棋盘。每次游戏、策略、地图/读档切换会重置当前运行保护；切后台立即取消待执行命令，前台仅从当前真实状态继续。
- **防循环**：不允许并发多个电脑动作；定时器关闭后检查原状态快照、储存忙碌、页面可见与暂停条件。按轮次和玩家计数，单轮成功的电脑动作最多 48，异常、非法动作与无合法行动均暂停并保留错误描述，绝不自动篡改状态“解卡”。
- **可观测性**：每次行动记录电脑策略/引擎命令的纯计算耗时（`performance.now`）、真实计划等待毫秒、命令数；显示决策累计耗时，禁止把计时器等待误称为 AI 计算速度。快进不改变场景脚本，降低动效时不影响回合。
- **验收**：`tests/p4-cpu-pace.test.mjs` 相同 72 个种子在两图、2～4 玩家三策略下完整跑两遍引擎，核对动作轨迹、胜者、经济、设施、股票与贷款精确一致。真实 Chromium `tests/browser_p4_cpu_pace_e2e.py` 同种子正常/快速三组尺寸（1440×900、390×844、320×640），记录从开始到胜负的墙钟耗时、经济摘要和状态 revision；另核实暂停后不能偷跑、真人接手不能被电脑自动操作。对比结果写 `artifacts/issue70/report.json` 并留截图。
- **阈值**：保持最终经济、回合和行动完全一致为硬门槛；仅当正常模式实际浏览器比 #69 统一 220ms 排队可节省显著时间且不掩盖关键事件时才称加速。CI 虚拟机墙钟测量会受负载影响，不等于真人玩家的主观体验；未收集真人意见，不宣称“好玩”。
- **兼容**：修改只在 UI 和测试；全部 P1～P3/P4 浏览器回归保持，游戏存档格式未修改。本地 IndexedDB 自动存档及离线 PWA 沿用原流程。
