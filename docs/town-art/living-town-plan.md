# 晴湾生活街区实施计划

> 执行方式：使用 `superpowers:executing-plans` 在当前任务分支连续实施，最后进行独立审查。所有者已授权实施及合并 `dev`，不等待计划审批。

**目标：** 将一张 `classic-24` 做成具有连续街面、多种建筑和日常生活设施的小镇，取代空草坪上重复房屋的观感。

**设计依据：** 2026-10-21 所有者否定上轮整体视觉结果，提供三张街区参考图。借鉴建筑体量、临街关系、公共空间和道具种类，不复制参考图素材。保留原创微缩语言。新局必须已经是一座小镇，不能等待玩家买完全部地产才出现城市。

**架构：** 扩展现有显式场景对象的模型种类；几何分件按形状实例合批，接入 `AuthoredScenery`。只重新编排 `classic-24.world`，不引入第二套场景系统。其地产使用独立形体族，其他地图保持现状。

## 全局约束

- 不修改价格、租金、随机数、规则拓扑、角色、骰子或存档结构。
- 地产 `0` 级仍为空地。取消墓园式围墙，产权与待售通过开放铺地、临街牌和地界表示。
- 所有几何沿共用地表落地，使用统一 PCF 光照与投影/受影策略。
- 远侧形成较高的商业街和公寓，近侧为低矮市场、花园及水岸，保留角色可见通道。
- 模型、景物、街道均有明确用途与位置，不在运行时随机填景。

## 审查重点

- 新局、未购地、四产权、0/1/2级、联排、抵押：可读且不出现围墙墓园。
- 默认/旋转镜头与手机：建筑背面完整，角色、路线与操作可见。
- 街面有前后层次，模型轮廓多样，不能靠重复同树同屋凑密度。
- 场景扩展仍有合理绘制成本、资源回收和拾取；其他地图不被改造波及。
- 完整对局、旧存档、离线、统一阴影及规则摘要继续通过。

## Task 1: 街区模型与主程序接入

接口：`urbanParts(kind, color)` 产生统一带形状/变换/颜色的部件；`UrbanScenery` 消费显式 `SceneObject`，复用实例批次和裁切。

- [ ] 先添加有意义的失败测试：未知形状/非法坐标、建筑与低矮道具高度分层、确定性与地表贴合。
- [ ] 实现咖啡馆、旅店、书店、面包房、公寓、温室、市场、工坊和不同树形；公交站/车辆/桌伞/摊车等独立道具。
- [ ] 接入真实主程序，以商业街和广场取代大面积无功能草坪；截图审查后再调整。
- [ ] 执行 `npm test`、主程序实际截图；提交接入断点。

## Task 2: 地产与街面整合

接口：`streetPropertyParts(tile, owner, seat)` 保持地块身份和原等级契约，供现有住宅实例渲染调用。

- [ ] 先测试未购地无围墙、0级不画住宅、升级明显改变形体、所有部件不侵占道路/邻地。
- [ ] 加入不同门脸/屋顶/楼层的地产形体族，联排表现为相邻住宅街面。
- [ ] 完成路缘、横道、街边设施与院前连接；核对真实产权/抵押/点击。
- [ ] 执行规则、构建及桌面/手机真实操作；提交。

## Task 3: 整体画面与性能

- [ ] 对比同存档/镜头/视口的新局和已建局，检查全景、近景、旋转与手机。
- [ ] 收敛密度、材质、空间层次与遮挡；记录真实缺陷，不能以物体数量或测试替代视觉判断。
