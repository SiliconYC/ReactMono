# 3D demo 金融与胜负演出验收（#88）

来源：[P005](proposals/P005-classic-mechanics.md)、[P006](proposals/P006-3d-art-renewal.md)、[#88](https://github.com/SiliconYC/ReactMono/issues/88) 及所有者对本地 demo 的定向要求。自 `dev@9e88bda` 建立 `codex/demo-economy-outcomes`，集成目标和 PR base 均为 `dev`。

## 玩家可用的变化

- 买地、建房、升级只对掷骰后停留格开放，每次停留只能执行其中一次；买地后显示空地及下次到访提示。银行、证券等资金操作不会重新开放本次建设机会。同街区连续住宅的联排保持原有边界。
- 开局每人现金 1,200、存款 600，总资金 1,800。买地/建设扣现金，主动买股扣存款，卖股净收入回存款；租金不足会按核心规则提存、清仓；欠款可能导致抵押地产被没收，仍不足则破产并释放产权。本 demo 未启用自动出售未抵押地产救济。
- 回合中处理完当前地块后，可办理存款、取款、地产抵押/解押、借款、还款。抵押增加额度，借款才给现金；抵押期间不收租和建设，欠款高于解押后的额度则不可解押。沿用核心每轮存款 1%、贷款 2% 利息。
- 五家虚构公司使用独立种子行情，每轮更新价格；显示报价、涨跌、实际历史走势、持仓数量/成本/市值/浮盈亏，以及含手续费的买卖。手续费沿用 0.5% 向上取整、至少 1 游戏币。无外部行情或账户。
- 真实事件驱动移动→租金→破产退场→胜利庆祝，输入锁覆盖整段演出；破产角色保留至退场，胜者有跳跃、奖杯和彩纸，轮数结束及平局也有对应结果。减少动态效果使用简短静态提示，可跳过演出和重新开局。
- 银行有原创几何建筑；骰子与镜头继续跟随角色。桌面、手机及短横屏金融面板内部滚动，支持键盘焦点约束、ESC 关闭和恢复焦点。

## 规则和存档兼容

规则仍由核心纯命令执行，React/Three 不写经济结果。新增可选 `propertyVisitOnly: true` 和 `stockAccount: bank`；demo 显式启用，旧对局缺省继续远程建设和现金股票交易。v4 存档严格校验并保存新标记，旧 v1–v4 迁移及历史测试保留。demo 当前没有新增存档界面，不把核心序列化测试称为 demo 存读档功能。

## 验证与真实失败

- `npm test`：143/143 通过，包括新增到访限制、资金分账、存取/贷款利息、旧行为/存档兼容、真实结局事件、可复现 URL 配置；保留既有批量模拟。
- `python3 -u tests/browser_demo3d_e2e.py -v`：生产构建真实 Chrome 八项，覆盖桌面/手机金融闭环、非法输入/额度、跨轮图表、停留建设与联排完整局、租金、动态减少动画、短屏和真实破产后胜利。最终运行结果在下方记录。
- 种子 `36` 的真实 12 轮对局完成逐次建设、两户联排及轮数终局；种子 `1&rounds=24` 通过正常买地/建设/取款，在第 45 个玩家回合实际租金不足破产，验证正常动画下先退场再庆祝。URL 只配置种子和 1–60 轮长度，不注入骰子/余额/胜负。
- 金融真实账目：首购后现金 1,064/存款 600；存 100、取 50、抵押额度 51、借 40/还 10；青禾农业 55 元买 2 股含费 111、卖 1 股净得 54，存款到 593，现金不受证券交易影响；还清贷款后可解押。
- 开发期失败如实保留：首轮破产脚本误把建设动作写成银行导航，随后寻找不存在的关闭按钮超时；第二轮新增图表断言没有选中预期股票（默认海岚科技），修正测试选择，不改产品数据。最早并行接入新文件时 Vite 缓存缺失模块，构建通过后重启原服务确认恢复。
- 演出断言在操作前记录原子快照；CSS 入场淡入不触发 DOM 变化，另取样卡片不透明度至少 0.9 的可见状态。保留真实顺序、输入锁、金额和减少动画小于 700ms 的门槛，失败必关闭浏览器 context。扩展两套金融交互和 45 回合破产局后，将 CI 步骤超时由 6 分钟调至 10 分钟，不放宽产品响应门槛。

## 远程首轮超时与渲染修正

[首轮远程 CI](https://github.com/SiliconYC/ReactMono/actions/runs/39085138221) 的 Node 143/143 和 2,000 局模拟通过，3D 浏览器前六项通过，实际减少动画响应为 488.5/493ms；在第七项 45 回合破产局执行中达到十分钟总时限，后续回归因此跳过，没有将该轮作为可合并结果。24 回合减少动画局约 265 秒，桌面金融约 92 秒、手机金融约 30 秒；这些证据指向持续 3D 绘制和大量驱动交互的叠加成本，但首轮未记录 renderer，不能直接声称已证实软件渲染。

修正产品实际无效工作：金融模态面板打开时暂停背景 Canvas；减少动态效果且无演出时按需绘制，角色与追踪目标在布局阶段直接同步，避免单帧停在插值中途或读取旧相机目标。正常骰子/行走/租金/结局保留持续绘制和全部原验收门槛。新增仅测试环境的真实 WebGL draw 调用计数，要求金融背景和减少动画闲置 150ms 内零绘制，同时记录实际 renderer；未再增加十分钟总时限。最终增强版与远程重跑结果见 PR 最新检查。

独立增量审查发现按需绘制时切换视角没有请求新帧；新增绘制计数增加和 canvas 截图实际变化的断言先复现失败，再由 Scene 布局阶段统一请求需求帧，最新联排截图已正确显示居中全景，审查确认该 P2 关闭。最终本地 Chrome **8/8，85.944 秒**，媒体响应 **13.8/11.7ms**，金融背景和减少动画闲置绘制增量均 **0**；实际 renderer 为 Apple M1 的 ANGLE Metal，不能据此冒称云端性能已改善。Node 重跑仍为 **143/143**。原始证据已更新，首次超时原始片段另存于证据目录。
