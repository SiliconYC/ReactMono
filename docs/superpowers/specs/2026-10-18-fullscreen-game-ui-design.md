# 主程序全屏游戏界面设计

## 目标

把当前“3D 棋盘 + 页面标题 + 纵向设置/状态侧栏”的工作台式布局改成主流桌面游戏界面。玩家进入应用后始终看到铺满视口的 3D 小镇；游戏信息与操作作为贴近场景的 HUD，需要时再展开。开局与结算各使用一个轻量覆盖层，不引入新的页面导航或服务。

## 用户意图与约束

- 主程序应以游戏世界为主视觉，消除大块页面背景、宣传标题和常驻表单对首屏的挤压。
- 常用操作不应被藏入多层菜单；次要信息可收进可展开面板。
- 本机多人、AI、两张地图、金融、卡片、引导、存档/导入导出、离线与现有规则语义继续工作。
- 所有游戏文本保持简体中文；静态 GitHub Pages/PWA、本地存档、不接后端不变。
- 桌面与手机使用同一游戏屏幕；窄屏允许 HUD 调整位置和单列面板，但页面本身不滚动。

## 屏幕结构

1. **开局屏**：全屏 3D 小镇作为背景。一个精简的开局面板展示地图、人数和醒目的“开始游戏”；种子、玩家昵称/真人电脑配置、电脑策略、轮数、设施与速度进入可展开的高级设置。本地存档仍能恢复旧局。
2. **对局屏**：3D Canvas 固定铺满视口。顶边只留品牌、状态和少量系统控件；当前玩家、现金与轮数以小型 HUD 呈现；当前阶段的关键动作仍在触屏可达的操作卡内。资金、玩家全员资产、事件、地块列表/信息、存档和帮助通过轻量抽屉/菜单按需展开。对局屏不显示宣传标题、网页式卡片网格、站点页脚。
3. **结算屏**：保持棋盘与玩家在背景中，显示居中的胜者/平局、原因、最终资产和“再来一局”。不创建额外结果路由。

## 布局实现

复用 `App` 现有规则状态与 DOM 控件，不移动或复制经济逻辑。新增全屏专属样式，通过 `data-game-status` 为 setup/playing/finished 设置不同的 HUD 排布。`WorldCanvas` 与 fallback 继续使用同一完整视口；默认镜头展示整张地图，只在角色实际移动时跟随，避免静止时裁掉外围格。已有 `<details>` 面板作为本地 HUD 抽屉，默认收起并用不重叠的定位打开。操作内容使用 `100dvh` 安全区域和触屏最小尺寸，紧凑视口内面板自身可滚动。

## 验收

- 4174 默认启动页、真实对局和结算画面均无整页滚动，3D/fallback 区域覆盖视口。
- 桌面 16:9 与窄屏竖屏下，场景仍是主视觉；开局、掷骰、买地/升级、结束回合、银行/股票、存档入口仍可触达。
- 开始配置有醒目的主动作且首屏不铺开整张表单；高级设置可展开并正常开始配置的对局。
- 结算层不会遮断重开；旧存档、规则、PWA 和 4173 demo 服务不受 UI 改造影响。
- 保留实际本地构建与浏览器画面验收证据；本轮按开发者指令不新增或运行测试套件。

## 未包含

不改规则、AI、存档 schema、棋盘美术资产、真实手机性能目标或 P4 综合验收结论；不删除晴湾 demo。
