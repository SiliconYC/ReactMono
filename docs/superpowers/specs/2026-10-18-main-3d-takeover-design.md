# 主程序 3D 接管设计

## 目标与边界

将主程序首页和实际对局棋盘切换为晴湾小镇风格的原创低多边形 3D 街区，保留主程序 24/20 格地图、电脑玩家、卡片/设施、规则核心、IndexedDB 存档和 PWA 能力。晴湾 demo 中已有的建筑成长、连片住宅、银行/贷款/股票规则与结算演出继续复用核心规则及 3D 表现代码。demo 标为待退役并记录退役条件，本轮不删除源码，也不停止用户当前 4173 服务。

游戏规则与存档仍以 `GameState` 为唯一真实状态；Three 场景只投影规则状态并发出地块选择/镜头操作，不在渲染层复制或修改规则。主程序已支持的核心操作保持其原有入口，地块信息与操作继续用简体中文 DOM 显示。现有 3D 世界从固定 16 格切片扩为从 `GameMap.cells` 派生的经典 24 格与海港 20 格布局。超过两名玩家的颜色、同格站位和资产指示要可辨认。

## 方案选择

1. **建议：迁移主程序 React 运行时到同源 Vite bundle，并将现有 R3F 世界嵌入原有完整 UI。** 一套 React 实例即可复用 demo 世界/演出；保留旧主程序已有完整规则和存档交互；代价是调整前端入口与 PWA 资源清单。
2. 将 demo 独立页面扩成完整游戏。会复制主程序已有新局配置、电脑、存档和设施流程，长期形成两套产品入口。
3. 在 UMD 页面中重写 Three.js 命令式渲染器。避免 React 构建变更，但复制场景、动画和交互逻辑，迁移维护成本最高。

选择方案 1。构建输出仍包含用于 Node 测试/兼容模块的 `dist/core`，页面运行时改为一个同源 ESM bundle；Service Worker 根据实际产物生成预缓存和版本指纹。主 UI 只替换平面棋盘主视觉，不移除已承载电脑、多地图、引导、交易、卡片、存档、导入导出的功能。

## 地图与交互

将规则地图格子坐标转换到固定斜俯视正交世界坐标。棋盘节点、连接路段、地产退界均按 `GameMap.cells` 和边界侧计算；环线规则顺序仍由 `map.route` 决定。动画使用同一地图坐标表，保证落点、经过节点和角色位置一一对应。中央保留原创小镇地标，外围的地块/建筑按现有 `Tile` 类型呈现，地名和完整数值由 DOM 信息卡提供。

场景负责显示角色、骰子、产权、建筑等级、抵押/路障和资金演出；玩家仍通过现有回合命令组件操作。点击格子更新既有选中格详情。WebGL 不可用时显示可操作的简化语义棋盘并保留全部规则操作。Reduced Motion 关闭跳跃和相机动画而不改变结算结果。

## 退役标记

在 demo 入口、项目文档、P006 与演进日志注明“晴湾小镇独立 demo：待删除”。删除条件为主程序 3D 入口完成经典/海港地图、AI/多人、设施/卡片、金融、旧存档读取/保存/离线与桌面/窄屏验收；当前变更不满足条件之前不删除 demo 源码/配置/验收证据。

## 验收与回滚

- 规则/经济/旧档测试不变且通过；现有全套规则与跨版本回归通过。
- 主程序生产构建能把 React、Three、R3F 和游戏模块打包为同源发行资源，Service Worker 缓存所有实际运行模块；不引入 CDN 或后端。
- 浏览器端实际启动/继续完整 3D 对局、点击地块、买地、升级/连片呈现、银行/股票、电脑行动、存档恢复；经典 24 格及海港 20 格均可玩。
- 3D 资源按全局场景策略 cast/receive shadow；地面贴合、不共面闪烁。桌面与 390px 窄屏主要操作可达。WebGL 故障时简化版可操作。
- `npm run dev` 在 `PORT=4174` 可打开主程序；既有晴湾服务 `127.0.0.1:4173` 不被重启或改写。
- demo 源码和原验收资料保留并带待退役说明，回滚主程序渲染入口即可回到已有 UI；存档 schema 不变。

## 风险与取舍

3D 增加首次下载体积和 GPU 使用。沿用仓库已提出的 3D 资源预算研究，不移除旧 PWA 离线覆盖，也不宣称真实手机 GPU/长时耗电已验证。旧 CSS 结构测试需要迁移到浏览器语义行为与画面验收，规则和存档断言不得删减。主程序已有的地产升级规则和 demo 特有“本次停留限一次/联排”配置语义要取舍一致：复用主程序可选规则并将正式新局开启地产访问限制；旧存档维持其既有兼容语义。
