# P3-04：数据驱动地图模型（Issue #33）

## 实现与兼容边界

- 棋盘使用 `GameMap` 数据声明：`id`、`version`、`columns`、`rows`、每格 `cells` 坐标及 `route` 移动序列。界面坐标与走格均读取同一份地图数据，不再硬编码 24 格和 8×6。
- 保留 `classic-24@1` 原有 8×6 环形；`internal-square-16@1` 是 5×5、16 格的内部回归地图，不是正式第二张主题地图（正式第二图属于 #34）。
- `createGame` 校验地图、分离复制拓扑；前进按 `route` 循环。地图严格匹配受支持的 ID、版本、格数、顺序及坐标；非法路径或篡改存档拒绝，不静默降级。
- 状态规则版本升至 v4；经旧版严格验证与校验和验证后，把 v1/v2/v3 存档安全升级并补充匹配的地图契约。现有两人经济、随机数和产权保留。
- Service Worker 将构建产物中实际存在的同源 JavaScript 模块自动预缓存，防止地图模块造成首次离线加载缺资源。
