# GitHub Pages、PWA 与本地存档：明确的纯前端方案

> **产品决定：仅使用静态 GitHub Pages 托管准本地游戏。** PWA 离线可玩、本地多存档与手动导入导出；**不做账号、登录、云同步或游戏服务器**。游戏界面仅简体中文。此处为架构约束，尚未部署。

## 1. GitHub Pages 是否足够

足够承载无需服务器实时运算的单机/本地多人回合制游戏。浏览器负责运行规则、界面、动画、电脑玩家及本地存档。服务器仅传送编译后的 HTML、JavaScript、图片和音频。

预期项目地址（**尚未启用，不能视为当前可访问**）：https://siliconyc.github.io/ReactMono/

若后续采用 Vite，仓库项目页应配置资源基础路径 `/ReactMono/`，并检查页面刷新、静态资源和客户端路由在子路径下是否正常。

GitHub Pages 不提供游戏服务器或账号数据库；本项目明确不建设这些功能。未来无需为此预留云端后端工程。

## 2. 不注册账号的推荐方案（首选）

- **新建游戏**：纯客户端初始化游戏状态，不需要联网请求。
- **多个存档位 / 读档**：用浏览器 IndexedDB 存储完整的、带版本号的游戏状态。
- **自动保存**：在回合结束及其他定义好的安全节点写入，并提供保存完成/失败提示。
- **手动导入/导出**：JSON 存档文件，便于用户自己备份与恢复；导入时严格校验格式及版本。这不属于跨设备自动同步。
- **轻量设置**：音量、界面偏好可用 localStorage，而不是把大量游戏状态都塞进去。

重要限制：浏览器的清理操作、无痕浏览、存储压力、切换浏览器或设备，都可能使本地存档不可用或被删除。必须向玩家提供清晰的本地存储提示，并支持文件备份；必要时可以请求持久化存储，但不能保证所有浏览器都批准。

存档应考虑 `schemaVersion`、玩家/棋盘/经济/回合状态、随机数状态和必要事件，使用迁移/兼容测试防止升级毁档。存档是数据，不应作为可执行脚本载入。

## 3. 不建设用户系统

产品边界已确定：不提供游戏注册、登录、云端存档、跨设备自动同步或多人联网对战；也不为了潜在的未来需求引入认证服务或数据库。纯本地存档的丢失风险由清晰提示、导出备份和恢复流程缓解。

## 3.1 PWA 离线验收

- 首次联网加载后，下载必要的程序与资源；随后断网能从同一设备打开并玩完整对局。
- 离线状态下可新建、保存、读取，并能够在恢复网络后安全更新缓存。
- 版本升级不能无提示损坏旧存档；存储不可用时展示简体中文说明。

## 4. 将来如何部署（现在不执行）

- 开发与整合仍以 `dev` 为准，不以 `main` 作为默认部署来源。
- 可采用 GitHub Actions 从 `dev` 编译并部署 Pages；若不启用 GitHub 托管执行器，也可在受控的外部/本地环境编译静态产物，再发布到配置的 Pages 来源分支。
- 部署属于显式启用的后续事项；应先验证构建产物、路径、存读档及页面刷新行为。
- 本仓库初始化阶段不创建部署工作流、不设置 Pages、不申请后端服务、不接入付费依赖。
