# P006 · 真 3D 低多边形街区与前端表现重建

- 日期：2026-10-17
- 状态：整体正式版目标**继续研究**；16 格本地 3D 切片已实施，2026-10-18 的有限升级晋升 #86，正式 24 格/AI/PWA 适配仍未交付
- 来源：所有者指出原型与正式经营游戏的画面、角色和玩法体验存在显著落差，要求比较 N 方向图与 Crossy Road 式低多边形 3D，并形成完整架构与动画文档
- 影响阶段：P4；关联 [P005](P005-classic-mechanics.md) 的玩法体验，衔接 [#73 最终综合验收](https://github.com/SiliconYC/ReactMono/issues/73)
- 方案入口：[美术与前端重建文档](../art-renewal/README.md)

## 观察与证据

`dev@a560589` 已有多地图、多人、经济、AI、保存与离线，119 项现有 Node 检查在本轮通过，包含 1,000 局完整混合配置验收。但主界面仍为 902 行组件、CSS 网格棋盘和 SVG 头像；反馈主要是文字与踪迹，而非角色在街区中的连续行动。种子 17 的真实浏览器开局/掷骰与截图确认了这个现状。

旧 P4 美术改造有真实交付价值，却不足以代表所有者要求的正式游戏品质。现有测试对体积、坐标和 CSS 的成功不自动等于画面和趣味性成功。[证据与边界](../art-renewal/07-evidence-and-sources.md)

## 方案比较与价值

比较八/十六方向 2D、真 3D 正交、3D 预渲染精灵。首选**低多边形微缩街区 + 固定斜俯视正交镜头**：角色动作与方向解耦，建筑/光照复用，连续移动与产权成长更直观。代价是建模/绑定管线、WebGL2 设备验证与更高资源预算。具体比较、成本结构与视觉标准见 [01](../art-renewal/01-art-direction.md)。

工程价值：保留纯规则、随机数、AI、存档与测试；新增应用协调层和演出层；替换绑在旧布局上的渲染/动画，不把旧代码规模当必须保留的理由。

## 争议与主要风险

1. 能否持续产出统一、完成度足够高的模型和动作，尚无生产证据。
2. 3D 不会自动改善玩法深度；对人物能力、岔路和对抗机制的研究仍与美术重建分开。
3. 现有整站 2 MB / JS 800 KB 硬测试与新方案冲突，必须显式评审新候选预算，不静默放宽。
4. 规则瞬时结算与动画延时展示之间，需要输入门、终态同步、epoch 取消、保存/更新屏障。
5. 手机发热、遮挡、离线资源和多标签更新不能以桌面截图推断达标。

## 晋升条件和首个交付目标

本设计经评审、首切片资源/设备门槛与构建迁移边界确认后，可先晋升少量 G0/G1 风险消解任务，再以证据决定 G2。首个产品目标是一张真实可玩到结束的 24 格 3D 地图，完整连接投骰、行走、买地/升级/收租、AI、保存和离线；独立看模型的网页不达标。

不得因为新架构就删除原测试保障。出现连续两轮有针对性的美术/性能修正仍不达标时暂停扩张，记录失败，评估同源模型八方向预渲染或重新选择 2D。回滚以旧渲染入口和不变的规则存档为基础，细则见 [06](../art-renewal/06-delivery-and-acceptance.md)。
