# P010：从可玩 Demo 到正式游戏的子系统与任务级开发计划

> 状态：开发规划，尚未执行本文任务。目标分支：`dev`。核查日期：2026-10-21。
> 源码基线：[`bd9891b530fea63b11f299a73a64bcda923b408e`](https://github.com/SiliconYC/ReactMono/tree/bd9891b530fea63b11f299a73a64bcda923b408e)。
> 本轮阅读当前代码、现有研究及验收记录，不冒充重新运行了游戏、重做了九仓研究或完成了真人试玩。后续 Agent 开工时必须重新核对 `dev`、开放 Issue 和已合入成果。

## 一、结论：保留参考文章的方向，重做执行层

参考文章的三项原则正确：按玩家可感知的功能划分；每次交付完整纵向切片；升级已有机制而非推倒重写。以美术和体验补齐产品短板，也符合 [#104 综合研究](../research/comparative-review.md)。

但它还不是可以直接派发的开发计划，主要问题如下。

1. **34 项是能力领域，不是 34 个等大的任务。** “角色造型”可能只交付一个角色，也可能包含四角色、骨架、头像与全部动作；“存档与确定性重放”跨多个数据契约；“一张高质量主题地图”又依赖建筑、镜头、经济与设施。不能仅给出标题就让 Agent 自行无限扩张。
2. **部分现状已经过时。** [P008](P008-authored-level-worlds.md) 已将背景改为显式关卡数据：逐格世界坐标、陆水轮廓和逐个景物。不得回到已被否定的自动填景方向。[P009](P009-map-camera-ux.md) 和 #120 已改进镜头、地图菜单与编号朝向；#92 已重做主界面。因此这些任务是增量品质升级，不是从零造地图编辑体系、镜头或 HUD。
3. **已有视觉联排不等于街区联合租金。** 当前 `rowHouses` 处理表现联排；`turns.ts` 仍按落点地产计算租金。改变收费是独立规则任务，绝不能混进建筑改模。
4. **上游不是九个已证实成熟的完整产品。** #104/#121 已指出源码、作者自述、限定实测和审美判断的界限。Yakamozli 的棋盘主要是整面 CanvasTexture；zawsstt 的首回合截图和建筑工厂不能证明全部升级过程、手机交互或正式版性能。它们提供参考，不替代本作验收。
5. **“先视觉、后规则”不是把可靠性推到最后。** 美术主线优先；命令、演出取消、存档恢复、资源预算必须伴随推进，否则后续每个任务都会推倒前一个任务。禁止先做六套独立展示页，再另外安排一个无边界的“总集成”。
6. **正式版不以填满原作功能清单为前提。** 分叉、公司控制、神明、小游戏都可以有价值，但它们不是“从 Demo 变正式”的必备勾选项。先把现有规则做得清楚、好玩、稳定，再用实验决定扩展。

本文把原清单重组为 **11 个长期模块、27 个首版任务包和 8 个条件扩展包**。这不是要求立即创建 35 个 Issue，也不是承诺恰好 35 次会话完成。任务包表示可派给一位 Agent 连续实施、测试并收口的边界；确有必要拆分时，必须按可独立验收的成果拆分，而非按文件数量或随意时间箱拆分。

## 二、首个正式版本的产品边界

### 2.1 建议锁定的交付范围

以下是本计划提出的首版范围，不是当前已经实现或验证的成绩：

- **一款主程序**：浏览器本机运行的原创低多边形三维经营棋盘游戏；纯静态 Pages/PWA、简体中文、本地存档及手动备份。不引入账号、游戏后端、联网房间或自动云同步。
- **两张精制正式地图**：优先精修现有 `classic-24` 和 `harbor-20`，形成明显不同的景观与策略节奏。60/120/360 格地图保留作扩展性与回归场景，不以“大”冒充正式内容质量，也不删除其存档支持。
- **2–4 人本机轮流游戏**：人类与电脑可组合；四个可辨认的原创角色外观。首版角色不新增专属数值技能，避免美术任务耦合平衡系统。
- **现有经济闭环完整可理解**：地产 0 级空地、1 级住宅、2 级高级住宅，到访购买/建设、出售、租金、银行、抵押贷款、五只虚构股票、清算与胜负。原有旧局规则与新局可选配置继续兼容。
- **有限而完整的策略内容**：现有五类卡片先做好合法时机、目标、取消与反馈；医院、监狱、商店形成清楚体验；随机事件做小批有区别的内容，不一次增加几十种效果。
- **完整游戏体验**：开局、教学、回合、镜头、暂停/快进/减少动态、结算、重开、存读档、离线与升级，都能在主程序中使用。
- **真正的正式版门槛**：视觉品质、操作易用性、长局稳定性、性能、离线与旧档兼容分别验收。保留 [#73](https://github.com/SiliconYC/ReactMono/issues/73) 作为综合收口入口；本文不提前关闭它、不降低它的既有要求。

### 2.2 明确不在首版主线

不复制原版受保护人物/音画；不移植 C++、Godot、Cocos 或上游后端；不默认把五股改十二股；不默认改成原版联合租金；不做任意地图导入、关卡编辑器、完整公司控制、无限卡片组合、复杂神明系统、小游戏合集。条件扩展见第七节。

### 2.3 主程序与旧 Demo 的边界

主程序启动使用 `npm run main:dev`，地址为 `127.0.0.1:4174`；旧迁移 Demo 为 `npm run demo:dev`，地址为 `127.0.0.1:4173`。`src/demo3d/world/` 虽带 demo 名称，却已被主程序复用，不能按目录名误判为可抛弃代码。

本计划所有功能都进入主程序，不另外建长期平行的“正式版演示”。临时资产检查页、固定场景测试可以存在，但不能替代主程序接入。旧 Demo 的删除另看迁移验收，不借本计划擅自删除。

## 五、任务包的统一契约

### 5.1 什么任务可以交给一位 Agent

一个合格任务包必须有：唯一玩家结果；明确输入版本和前置任务；有限对象数量/场景集合；实现入口和禁止改动；可重跑的验收；兼容与回滚策略。Agent 应从当前已有成果开始，完成设计细化、实现、测试、独立复核和提交收口，而不是做完代码就把集成与截图留给下一个人。

以下情形需要拆分：同包要求同时引入新规则格式、新资产管线和全套 UI；资产数量不设上限；依赖另一个尚未确定的接口；验收需要另一包未交付功能；以“达到商业级”“完善所有体验”作为唯一完成条件。遇到这些情形，先保留已完成的可验收部分，补一个有独立成果的后续包，不无限重试。

### 5.2 每包通用完成定义 G

以下 G 是所有任务卡的组成部分，不必复制进每张卡：

1. 开始时核对最新 `dev`、本包来源与开放 Issue。已有成果先验收和复用，不重做；本地 Agent 以已打开的正确工作区为起点，不要求重新克隆；在线 Agent 以远端 `dev` 和任务入口为起点。
2. 提交功能、必要测试和简体中文验收记录。每个断言记录真实结果、命令、环境、SHA、固定种子/存档、失败和缺测；游戏画面须真实运行截图，不是生成概念图。
3. `npm test` 为核心构建/规则回归入口；涉及地图再跑 `npm run maps:validate`；影响共享三维代码再跑 `npm run demo:build`。浏览器脚本按本包指定执行并核对其服务地址、浏览器依赖和断言适用性。旧脚本仍检查 2D `.tile` 时必须迁移到等价行为，不删除断言假装通过。
4. 修改规则/状态/地图身份的任务必须覆盖旧存档、非法命令、确定性以及电脑合法动作；显示层任务不得改变同一命令序列的最终规则状态。
5. 通过独立审查及相关实测后合入 `dev`；有严重未知回归不能标完成。不能把文件存在、截图存在、测试数量增加当作品质提升。
6. 每包回滚以对应提交为边界；保留用户存档。显示层不写新存档字段；数据格式变化须带兼容策略，不能靠清空 IndexedDB 或删除旧地图来回滚。
7. 本计划不自动授权发布正式服务。代码合入与正式发布分开；发布资格和必要权限在 T26 核查。

### 5.3 证据最低口径

视觉包固定同一地图、局面、相机、画质和视口，提供改前/改后：1440×900 桌面、390×844 竖屏；另按场景补窄屏与四人同格。必须检查真实操作状态，不能仅截开局。语义判断包括归属、等级、当前行动者和操作对象是否清楚；美术评语和真人反馈分开。

软件 WebGL、模拟手机视口只证明该环境结果。正式移动体验必须登记真实设备；没有真机就标未验证，不捏造 FPS。资源预算继承当前测试门槛；较宽的旧设计“候选预算”不自动覆盖已经执行的更严格门槛。

## 六、首版正式游戏任务卡

### T00｜锁定现状与可重复验收场景（首批）

- **目标/输入**：把当前主程序变成后续可比较的真实基线，不再以旧截图判断最新产品；输入本基线和 #73。
- **范围/入口**：选 24 格、20 格、360 格各一个固定局面；24 格增加 0/1/2 级地产、四人同格、抵押、收租、破产和终局场景。复用规则命令生成可导入存档，不写测试专用绕过规则接口。整理 `tests/browser_main_game_acceptance.py`、`browser_main_runtime_e2e.py` 和相关已有脚本的运行入口。
- **依赖/不做**：无；不全面重写测试框架、不修所有体验问题、不重新研究九个上游。
- **验收**：第三人按记录可构建、导入样本、截图并执行关键动作；每个样本有 seed、生成步骤、预期状态和哈希；记录当前实际失败，不把失败基线算通过；产出首批已去重缺陷列表与可执行脚本。
- **交付/回滚**：基线场景、少量脚本适配和证据索引；只改变验证工具，不改变玩家规则。满足 G。

### T01｜建立可在游戏中复用的美术样板与资产约束（首批）

- **目标/输入**：让后续角色、建筑、地景遵循同一视觉语言；输入 T00 与已有美术方案，采用原创低多边形方向，不重新开一轮无穷风格研究。
- **范围/入口**：一组材质/配色/比例规则，应用到主程序一个街角（地面、道路、0/1/2 级房屋占位、一个角色、一个设施）；统一场景光照/阴影。新增资产登记字段：来源、许可、编辑源、导出命令、运行时路径、字节/三角形/材质预算。入口 `WorldCanvas.tsx`、`MiniatureTown.tsx`、`SceneryModels.tsx`。
- **依赖/不做**：T00；不重做全部地图和四个角色，不引入未许可资产，不按个别物体关阴影规避瑕疵。
- **验收**：街角真实主程序双视口对比；近/远景、相机旋转、角色重叠无明显悬浮/闪烁/阴影断裂；预算统计可复现，资产登记与打包产物一致；独立评审能指出选定风格的具体规则。
- **交付/回滚**：复用样板、材质/资产约定、视觉基线；回滚表现代码不影响存档。满足 G。

### T02｜道路、产权地块与地图点击辨识（首批）

- **目标/输入**：玩家能分清可走道路、所属地产、所有者、等级、抵押和选中对象；输入 T01。
- **范围/入口**：先完成 24 格主图的地砖/地基/连接道、归属和抵押符号，再验证同一渲染逻辑用于其余图。入口 `MiniatureTown.tsx`、`layout.ts`、`RoadLabels.tsx`、`map-picking.ts`；保留现有显式世界坐标与实例化。
- **依赖/不做**：T01；不改 `map.route`、地价、租金、持有者规则；不重画五张图全部景物。
- **验收**：0/1/2 级、四种归属、抵押、无人地、旋转/缩放状态均可辨认；点击投影返回正确 tileId；360 格与弯道不遮路、不失去地块；地图/拾取单测、实际浏览器点选及双视口截图通过。

- **范围/入口**：记录初始配置与种子、规则版本、被接受的命令序列和状态指纹；提供本地测试/诊断导出与回放校验，不先做时间轴播放器。区分命令输入和派生事件；失败命令不改变游戏。
- **依赖/不做**：T00；不重写 reducer/引擎、不上传用户数据、不承诺任意历史版本都跨版本重演一致。
- **验收**：相同版本同序列逐步状态一致；快慢/跳过演出不影响结果；日志截断、未知命令、非法 actor、版本不符给明确错误；固定存档中途续接与从头回放等价；至少 100 种子局用于本包快速回归，正式收口仍执行 T26 的至少 1000 局。
- **交付/回滚**：小型日志格式、回放工具、差异定位及测试；旧存档继续可用，回滚可忽略诊断日志但不能误读新规则。满足 G。

### T20｜存档失败、导入校验与恢复闭环

- **目标/输入**：刷新、异常关闭或坏文件不会把一局游戏无声丢失；输入 T19、现有 schema 4 与 IndexedDB。
- **范围/入口**：自动/手动存档错误呈现、最后成功保存提示、重复导入、损坏/超大/不支持版本拒绝、可恢复备份和迁移验证。优先复用 `save.ts` 和 `indexeddb.ts`，不新造存储后端。
- **依赖/不做**：T19；不做账号、云备份或自动上传日志；不通过清空全站数据解决错误。
- **验收**：旧档样例、当前局 JSON 往返、保存事务失败/配额不足、取消导入、旧地图隐藏后仍可恢复、演出中刷新、迁移失败保留原档；主程序通过真实导入导出/关闭重开流程，不直接写测试私有状态代替。
- **交付/回滚**：迁移与恢复策略、用户可理解的错误和测试；格式变化先保存可导出的原始数据并有明确回退路径。满足 G。

### T21｜完整离线包与安全更新

- **目标/输入**：一次完整缓存后可以断网开始和继续两图游戏，升级不混用新旧资源；输入 T05/T09/T11/T15/T17/T18/T20 的资源与界面形态。
- **范围/入口**：资源 manifest、动态 chunk/模型/音频离线覆盖；新旧版本切换、下载中断、多标签页、存档兼容与更新提示。复用已有 Service Worker/构建流程。
- **依赖/不做**：T05、T09、T11、T15、T17、T18、T20；不引入运行时 CDN、不无提示强制刷新正在进行的对局、不把全新未缓存离线安装当可实现承诺。
- **验收**：清缓存首次在线→完整缓存→断网重载→两图开局与存读档；两个实际发行构建版本升级，中断不损坏旧缓存/存档；缺资源有明确可恢复提示；网络记录证明运行时无外部必需请求。
- **交付/回滚**：缓存/更新证据和资源清单；任何后续新增资源、动态入口或打包策略改变均使对应离线证据失效，T26 必须针对最终构建重跑全量离线/升级验收；回滚资源版本不删 IndexedDB，若存在格式不兼容须阻止静默回滚。满足 G。

### T22｜电脑决策的一次有对照改进

- **目标/输入**：电脑不是只会合法点击，而能围绕现金风险、投资和卡片时机作可解释决策；输入 T13–T16、T19。
- **范围/入口**：在已有三风格上只做一轮限定改进：购地/升级储备、债务风险、遥控骰/免租/路障时机；使用公共合法动作，不让电脑读未来随机结果。保存旧策略用于同种子对照。
- **依赖/不做**：T13、T14、T15、T16、T19；不做机器学习训练、搜索所有未来、多线程服务或修改经济来掩盖策略缺陷。
- **验收**：固定局势至少覆盖资金紧张/可升级/将付租/可免租/将违约/商店选择；旧新策略同配置至少 1000 局对照，记录胜率、提前破产、非法动作、决策耗时与局长；改进目标在执行前登记，不能只挑赢的种子；真实浏览器电脑无卡死。
- **交付/回滚**：策略差异、对照数据、失败局与回放；若总体退化保留旧策略为默认并如实报告实验结果，不强行宣布提升。满足 G。

### T23｜两张正式图的经济平衡与局长收敛

- **目标/输入**：两图有真实选择且不因单一必胜策略、无尽拖延或过早破产破坏体验；输入全部首版规则、T10/T11/T22。
- **范围/入口**：分别评估两图的现金、地价/租金、利息、卡片价格、轮数默认值；一次仅改变少量有证据参数，通过版本化新局配置保留旧档语义。五股数量和基本账户规则保持。
- **依赖/不做**：T10、T11、T13–T16、T22；不把胜率平均当趣味性，不将每次平衡都变成新系统开发。
- **验收**：至少 1000 独立固定种子混合配置对照，分地图/人数/电脑风格报分布，记录局长、破产时点、收益来源、策略占优及无法结束案例；至少三次真人体验记录用于解释节奏（可与 T26 合用但标清来源），没有真人就保留该缺口。执行前写明目标区间和依据，不事后挪门槛。
- **交付/回滚**：参数版本、模拟数据、真人观察或缺测、采用/拒绝理由；可切回上一配置，新档明确绑定版本。满足 G。

### T24｜资源预算与长时渲染性能收口

- **目标/输入**：提升画质后仍能实际游玩，不让正式地图被模型体积和过量渲染拖垮；输入 T10/T11/T17/T21。
- **范围/入口**：测两图、360 压力图、满建四人和主要演出；优化实际瓶颈，处理实例化、可见性、资源释放和画质档。延续全场景阴影规则，不任意挑物体关阴影。
- **依赖/不做**：T10、T11、T17、T21；预算约束从 T01 就生效，本包是最终综合实测，不是最后才开始考虑性能；不重写渲染引擎。
- **验收**：遵守当前 `tests/p4-release-budget.test.mjs`（现有 total 8,000,000 B、JS 2,500,000 B、CSS 180,000 B 等；实际以开工版本为准），新增资产需扩展清单覆盖而非绕过统计。两图各连续 10 分钟操作，记录硬件/浏览器/分辨率/画质/帧间隔/资源数；连续 20 次换图/重开稳定回收；无真实手机不宣称手机性能通过。性能目标与既有已批准门槛对应，候选值变更单独说明。
- **交付/回滚**：可重跑性能场景、原始样本、瓶颈修复和设备矩阵；必要时回退高负载资产，不降低产权/操作可读性。满足 G。

### T25｜异常恢复、键盘与减少动态的统一保障

- **目标/输入**：图形/音频能力不足、失焦或资源失败时，玩家不丢失局面也不被锁死；输入 T07/T20/T21。
- **范围/入口**：WebGL 上下文丢失、资源加载失败、演出超时、浏览器后台恢复；弹层焦点、键盘导航、减少动态、色觉冗余标记。复用已有错误/设置入口，不泛化成新无障碍框架。
- **依赖/不做**：T07、T20、T21；不承诺所有浏览器/辅助技术完全合规，不用自动刷新抹掉故障证据。
- **验收**：故障注入后可恢复、保存/导出或清楚退出；不会重新结算同一动作；仅键盘完成开局/掷骰/买地/保存，减少动态可完整玩局；弹层开关恢复焦点，视觉状态不只靠颜色；错误日志不含不必要个人数据。
- **交付/回滚**：有限故障矩阵、恢复路径和真实操作证据；降级方式必须保留现有存档。满足 G。

### T26｜正式候选版独立综合验收与发布准备

- **目标/输入**：证明前面的任务合起来是一款游戏，而不是多个互不相干的模块；输入 T00–T25，复用 #73，不重复开一个互相争抢的总验收入口。
- **范围/入口**：在固定候选 SHA 上独立复核全部退出门槛，建立阻断/非阻断缺陷清单、内容与许可证清单、版本说明、恢复/回滚步骤。发现缺陷回到对应任务修复，不把验收包变成无限重构。
- **依赖/不做**：所有首版任务通过；不因缺设备/缺真人/发布权限不足而伪造成功，不擅自发布正式服务。
- **验收**：至少 1000 独立模拟与不变量验证；两图 2–4 人、真人/电脑组合、完整胜负与轮数上限；真实浏览器桌面和手机视口完整对局、离线、导入导出、更新、画面/性能；#73 要求的公网验证与真实用户反馈分别补证。模拟手机与实体手机、代理实测与真人反馈严格分开。至少 3–5 次真人试玩目标沿用既有美术验收，不可用自动截图替代；有缺项则只标“候选版/部分验收”。
- **交付/回滚**：独立报告逐项链接 SHA、命令、结果与失败证据；只有全部强制项满足才建议 #73 关闭。公开发布需另核权限及已有流程，发布后检查实际版本/缓存/首局，回退前保护存档。满足 G。

## 七、条件扩展任务：明确入口，不挤占首版收口

这些包仅在首版体验数据或具体关卡需求证明必要时晋升。每包依然执行 G；不能把“已列在本文”当作实施批准或已经完成。

### C01｜分叉路网的纯规则与兼容切片

触发条件：某个已选关卡方案确需让玩家选择路线，且不能用现有单闭环表达。输入 T19/T20。交付一张只有两个分叉点的内部测试图、邻接边/方向/剩余步数/等待选择契约、合法路径验证和版本化存档迁移。测试反向、环、死路、跨起点/绕圈与既有结算、路障、读档待选（不额外引入起点奖励）；不做 UI 和正式地图，不强改所有旧图。通过后才允许 C02；未通过不将新拓扑设为默认。

### C02｜分叉选择的主程序与电脑闭环

依赖 C01。同一内部图接入主程序选择箭头、取消/恢复、镜头和电脑合法选择，完成完整局和读档续走；普通/快速/跳过模式同终态。先只采用一个简单可解释的电脑选路评价，不做全局规划器；正式关卡采用另经评审。交付包括路径逐边演出证据，不只到达正确终点。

### C03｜街区联合租金的可选规则实验

触发条件：T23 显示逐格收费缺少有价值的街区策略。依赖 T13/T19/T20。定义原创规则的街区身份、同主筛选、等级、抵押、免租、清算作用顺序，以显式版本化配置启用；旧局继续逐格收费。用 #104 的 1200/12000 例子理解上游边界，但不直接宣称本作必须采用原版公式。交付纯规则、预览解释及至少一张图完整局；不同时加物价、商业连锁和公司控制。规则不变量/旧档/AI 均通过后才进入 C04。

### C04｜联合租金的独立平衡与是否采用决策

依赖 C03。用两种收费模式、同地图/种子/电脑策略至少 1000 局对照，检查现金压力、集中持有优势、局长和新手理解；给出采用、保留可选或拒绝。需要 UI 与真人体验补证，不能用高平均租金冒充更好玩。只改有限参数，不又改一套经济；拒绝实验也属于有效交付，默认模式不被悄悄替换。

### C05｜两个持续人物状态的有限框架

触发条件：已确定的内容确需跨回合效果。依赖 T15/T19/T20。先做两个原创状态，明确持续单位、叠加/替换、到期、破产/拘留/读档规则，并在 HUD 和核心事件中一致呈现。不直接照搬整套神明、附身美术或原作文案。固定用例覆盖到期前后与跨轮边界；电脑评估、存档迁移一起交付。

### C06｜三张新增卡片的内容包

触发条件：T14 已稳定且玩家反馈表明确有策略缺口。依赖 T14，若含持续效果再依赖 C05。只选三张作用明确、不重复已有卡的原创卡片，每张交付时机、合法目标、取消、效果/反制、电脑使用、商店价格和旧档兼容。逐卡测完再全局模拟，不做自由脚本卡片系统；三张的选择理由和去除低价值设计也要记录。

### C07｜企业控制权的隔离经济原型

触发条件：已有五股买卖与地产策略确实不足，且首版已收口。依赖 T23。只选一个虚构企业、一个关联效果，明确流通量/控制阈值/并列/易主/清算与资产估值；放在可选规则下做纯规则与有限 UI 实验。至少 1000 局不变量/极端持仓测试和可解释对局后作继续/拒绝判断。不承诺十二企业全套，不复制原作企业资料，不能改变既有股价随机源而未版本化。

### C08｜一个可跳过的原创小游戏试验

触发条件：真人反馈证明短暂插曲有助于节奏，而非为了凑原作清单。依赖 T23。只做一个 20–40 秒小游戏，支持键盘/触控、跳过、后台/刷新恢复、固定最大收益与确定结算；电脑有等价且可测规则。小游戏失败或跳过不能卡住主回合，不新增服务器或新存储。比较加入前后真人等待感与收益影响；若打断主体验则不上默认模式。

## 九、质量门槛与停止条件

### 9.1 三个独立关口

- **功能关**：玩家确实能执行完整操作；钱、位置、阶段、身份、存档都一致。
- **表现关**：真实主程序中看得清、有形体、动效有因果；同场景对比有实质改善，不用“很精美”自评放行。
- **产品关**：跨系统完整局、离线更新、设备性能和真人体验成立。前两关通过不自动通过产品关。

每批后必须用两张正式图各跑一次真实主程序烟测；规则改动再跑模拟与迁移。烟测不能代替 T26 完整独立验收。

### 9.2 不能被弱化的边界

- 持续使用统一全局光照/投受影策略，不因模型较小而关闭阴影掩盖问题。
- 演出只消费规则结果；跳过、掉帧、音频失败和镜头变化不能影响骰子、余额或胜负。
- 改变地图逻辑拓扑不能覆盖已发布地图 ID 后让旧档失效；新的规则几何需新身份并保留旧定义。只改 `world` 则验证规则摘要不变。
- 资源清单覆盖所有运行时文件；不得把大模型移到未计数路径来“满足预算”。
- 许可证、真机与真人缺口必须保留。上游跑过小样例不能被升级成原版规则正确或我们正式版合格。

### 9.3 失败后的收口

连续尝试仍不能达到本包门槛时，交付固定 SHA、失败场景、已证实原因/未证实假设、可恢复断点和缩小后的下一步。可合入独立有效成果时注明未满足部分；不能关掉失败测试、重命名目标或悄悄改变验收以求“完成”。

无需为了一个非阻断瑕疵停住其它独立任务。阻断项与普通瑕疵分别登记：规则/存档丢失/卡死等阻断同批收口；外观微调可后续迭代，但不能以此放行仍像灰模的整套表现。

## 十、从本文派发一个任务的方法

派发时只选一个任务 ID，附上该卡与 G，不把整篇文档作为“全部做完”的单会话任务。
