# P001｜六阶段路线图及阶段退出标准

- **主题**：目标与路线图
- **来源**：原拟发布的 Discussion D01
- **阶段**：P0（影响 P0–P5）
- **状态**：阶段基线已在 ROADMAP 采用（2026-10-15）；后续以证据持续复核。本提案不等于执行任务
- **归属**：[候选池](../EVOLUTION_POOL.md) · [路线图](../ROADMAP.md)

## 要解决的问题

项目有两个不同的长期目标：①真正完成完整、稳定、好玩的《大富翁4》风格简体中文游戏；②验证 AI 能否围绕这些目标自主发现方向、筛选、实现、测试、审查并持续改善。不能让第二个目标吞噬第一个。

如果缺少阶段性可验收目标，自主代理可能长期优化边角或囤积大量 Issue，却始终无法交付玩家可以玩完的一局。

## 初步方案：六个能力阶段

| 阶段 | 面向玩家的结果 | 自主进化的实验证据 |
| --- | --- | --- |
| P0 目标与治理 | 明确准本地、简体中文、分支约束、阶段门槛 | 提案池→准入评审→Issue→PR→独立验收的规则 |
| P1 第一局能玩到底 | 一张小地图、回合、骰子、买地、收租、破产和胜负 | 首次完整的 AI 发现/拆解/开发/验收链路 |
| P2 可靠准本地版 | 土地升级、基础卡片及事件、静态网站、PWA、离线和本地存读档 | 缺陷反馈与回归防线 |
| P3 玩法丰富版 | 股票、银行、地图、建筑、道具、特殊事件、电脑对手策略 | 从模拟和玩家体验中自主发现改进方向 |
| P4 高完成度版 | 音画、动画节奏、可用性、性能、游戏平衡、稳定性 | 独立视觉与体验验收、真实回退数据 |
| P5 持续进化 | 小步优化持续发布，不破坏已完成的玩法 | 尝试至少 30 轮可审计的自主改进 |

这些阶段定义的是**退出能力门槛，不是固定工期**。P5 的自主进化成熟度不意味着 P0–P4 可以不用自主研发；实验从初期就开始进行。

## 需要研究的分歧

1. 哪些能力必须作为上一阶段的退出门槛，而不是之后补做？
2. P1 是否允许首版使用同机轮流玩家替代电脑玩家？如何防止这样削弱单人体验？
3. PWA、存档应在 P1 做最小兼容设计，还是 P2 再完整交付？
4. 怎样防止阶段目标重复、增加不必要的设计负担？

## 本轮评审结果（2026-10-15）

- 保留六个阶段，不因路线图本身创建“实现全部游戏”类 Issue。
- 正式批准先以 P1 的单人对电脑完整对局验证产品闭环；P2 再交付 Pages/PWA/本地存档。
- P1 首批五项任务链接及依赖参见 [P002](P002-first-playable.md)；本文件仍然是阶段目标，不是任务堆。

## 候选晋升条件

本提案本身不直接晋升为一张“写完全部游戏”的 Issue。只有阶段验收中识别出**当前阶段确实缺失、范围可独立验证**的具体工作，才能创建实施 Issue。

长期有效的决定更新 [ROADMAP.md](../ROADMAP.md)，并在 [决策及演化记录](../EVOLUTION_LOG.md) 留痕；被否决的方向也保留原因。
