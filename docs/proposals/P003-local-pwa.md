## 不可自行变更的产品决定

- 只使用静态 GitHub Pages 承载网页游戏；全部游戏规则和电脑对手在浏览器本地运行。
- 可以将网站作为 PWA 安装，资源完成缓存后断网也能继续玩。
- 存档在本机 IndexedDB 中保存，支持新建、多个存档位、读档、自动保存，以及手动导入/导出文件。
- **不做**用户注册、登录、云存档、跨设备自动同步或运行时游戏后端。
- 玩家可见界面及提示**只用简体中文**，早期不建英文版和多语言系统。
- 开发与默认集成分支始终为 `dev`，不向 `main` 提交。

上述决策不是给自主 AI 自由扩张的议题；可以比较实施技术，但不能暗中重新引入账号、服务器或者英文 UI。

## 仍需评估的实施选项

1. **静态部署**：构建产物如何适配项目页的 `/ReactMono/` 路径、刷新和静态资源引用？
2. **离线缓存**：首次资源缓存何时宣布完成？版本更新如何避免旧脚本与新资源混用？
3. **存档模型**：何时定义 `schemaVersion`、固定随机种子/事件和兼容迁移策略？
4. **持久化**：浏览器清理数据、空间不足或私密模式导致保存失败时如何提示及备份？
5. **可验证性**：如何测试断网启动、离线新建/读档、完整对局和恢复网络后的安全升级？

## 晋升规则与候选验收

将可独立验收的存档模型、浏览器存读档、PWA、构建部署逐项筛选进入 Issue，不为未来用户系统预留复杂基础设施。

候选验收包括：首次加载缓存成功后断网仍可新建并完整玩一局；关闭重开后能读回存档；导出后重新导入可恢复；页面升级不无声破坏旧存档；错误提示全部简体中文。
