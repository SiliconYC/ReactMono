# P012：本机对局调试工具

## 观察与价值

2026-10-22，所有者要求能给每个玩家输入现金，快速看到指定轮数之后的局面，不再手动操作或等待前端逐步播放。当前真实规则和电脑策略可复用，但 `runSimulation` 只支持从新局开始，菜单也没有调试入口。

该需求是明确授权的开发辅助功能，适用于每张地图，减少检查地产成长、长期状态和局面回归的成本。查重后晋升 [#133](https://github.com/SiliconYC/ReactMono/issues/133)，不与 `#73` 的正式版综合验收混同。

## 方案与边界

采用从现有 `GameState` 继续的纯规则函数，加本机 `Web Worker` 批量执行。比逐帧自动点击更快；比独立伪造地产和移动结果更能反映真实规则。菜单中的专用弹窗负责输入，成功后一次性替换当前局面，失败或取消保留输入快照。

- 现金设置只改对应玩家现金，不改银行存款、随机状态、产权或玩家身份；不复活破产玩家，终局仅供查看。
- 从当前中途阶段推进至轮次增加指定数值；保留原 `maxRounds` 和提前胜负条件，不自动延长对局。
- 真人暂用基础策略，电脑保持既有策略。计算完成后仍保留真人/电脑身份。
- 沿用既有存档事件容量和动作安全限制；超过限制明确失败，不删除历史或静默截断。
- 不引入后端、账户、外部资源或云同步。

## 准入与验收

用户需求明确，可独立回滚；核心测试覆盖全地图和多个中途阶段，浏览器实际调用生产 `Worker` 并导出完整状态，与规则模拟比较。重点检查现金草稿、并发回包、取消、场景就绪、后续人工操作和离线运行。

计划见[调试工具计划](../superpowers/plans/2026-10-22-debug-tools.md)，结果见[集成验收](../maps/lime-garden/refinement-2026-10-22.md)。回滚工具模块、菜单接入及相关样式即可；调试后的现金和模拟结果仍使用原存档格式。

## 2026-10-22：代玩公平性修正与终局浏览

所有者反馈几十轮模拟容易电脑获胜，并指出终局遮挡棋盘。查重晋升 [#134](https://github.com/SiliconYC/ReactMono/issues/134)。上述“真人基础、电脑既有策略”是首轮历史方案，实测会污染经济对照，现已修正：后台默认统一使用平衡策略，电脑显式选定的风格继续生效，真实身份与正常对局策略不改。终局默认显示普通底部结果栏，详细结算按需打开；后台模拟到终局时自动收起调试窗口。

两图、两档资金和多种子对照、证据缺口、浏览器验收及回滚见[公平性与终局验收](../debug-tools/fairness-and-postgame-2026-10-22.md)。没有因这组结果改动租金、价格、利率或原轮数上限；不把有限样本解释成整体经济已平衡。

## 2026-10-22：长局输入与破产目标纠正

所有者后续截图完整复现为默认 2200 资金／36 轮，调试草稿未随模拟提交。上轮保留原轮数上限和分开提交金额的设计不满足当前使用目标，晋升 [#135](https://github.com/SiliconYC/ReactMono/issues/135)：新局默认破产决胜，限轮显式可选；调试输入与结束条件在成功快照中一次应用，取消／失败不提交。连同经营取款与账本边界实测见[长局验收](../debug-tools/long-games-2026-10-22.md)。上轮多种子结果是当时策略的历史记录，后续经营策略已变，不能当作新版本固定胜率。
