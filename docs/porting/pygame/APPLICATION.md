## 必须保持的循环顺序

参考先 `draw()`，再消费本批输入，随后观察核心新输出、消耗等待、在电影/消息/开场均不忙时推进骰子、泵表现队列，只有队列与所有表现均空才执行规则 `tick()`，然后再次观察，最后自动保存和更新音频。帮助或卡图弹窗同时阻塞该规则推进路径。声音自身持续播放不能依赖主线程每帧供料。

渲染先记住无待播变更的世界，再执行物品延迟；主板与原菜单作为底层，效果/转盘/月结/开场、价格卡停留页、原专属决策、消息、电脑施法/拍卖成交、卡图、数字板、帮助按源码顺序叠加。每次模态覆盖必须清掉底层命中；派发首个启用命中后立即清空整批旧按钮，防止同一事件批次触发旧决策。

原正式应用的 `draw_choice_dialog` 是参考本身对普通选择的通用路径，允许忠实转写它；不得拿它替代参考已有专属银行/股票/物品/小游戏等屏幕。地图决策必须先选中并居中，再二次点选或确认，八项分页保持选项原索引。

## 已确认的保存与参考边界

参考仅在 `can_save()` 允许的人类待命回合写原DAT和 `RICH4-RNG-1`旁车，读取后创建新会话；异常快照明确 `resumable_save:false`。它没有保存任意中途表现/闭包事务。Python交付必须区分原DAT兼容与完整运行检查点，不能以DAT无损编解码宣称阶段、历史、队列跨进程恢复。

手动槽1–5只在手动保存时改；退出/每个可保存日/托管前写AUTO。读取失败需完整保留当前会话/板面，先在候选对象中验证，成功后再安装。当前Python尚无正式槽位文件与完整检查点实现。

已复现的原物品重置抢夺越界、施法哨兵与报价口径差异见 [物品屏幕](ITEM_SCREENS.md)；正式异常恢复需明确决策和证据，不能为通过长局静默跳过真实规则。开局/结局影片与参考AVI缺失边界见 [辅助界面](AUXILIARY_UI.md)。截至此记录，正式Pygame主程序仍是资源预览，禁止称完整可玩移植完成。
