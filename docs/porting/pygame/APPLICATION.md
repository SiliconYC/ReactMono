## 必须保持的循环顺序

参考先 `draw()`，再消费本批输入，随后观察核心新输出、消耗等待、在电影/消息/开场均不忙时推进骰子、泵表现队列，只有队列与所有表现均空才执行规则 `tick()`，然后再次观察，最后自动保存和更新音频。帮助或卡图弹窗同时阻塞该规则推进路径。声音自身持续播放不能依赖主线程每帧供料。

渲染先记住无待播变更的世界，再执行物品延迟；主板与原菜单作为底层，效果/转盘/月结/开场、价格卡停留页、原专属决策、消息、电脑施法/拍卖成交、卡图、数字板、帮助按源码顺序叠加。每次模态覆盖必须清掉底层命中；派发首个启用命中后立即清空整批旧按钮，防止同一事件批次触发旧决策。

原正式应用的 `draw_choice_dialog` 是参考本身对普通选择的通用路径，允许忠实转写它；不得拿它替代参考已有专属银行/股票/物品/小游戏等屏幕。地图决策必须先选中并居中，再二次点选或确认，八项分页保持选项原索引。
