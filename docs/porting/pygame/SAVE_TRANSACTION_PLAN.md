# DAT与随机旁车写入恢复计划

## 合同与依据

固定参考`tools/native_game.cpp:1049`顺序写DAT与`RICH4-RNG-1`旁车，没有两文件提交协议。本增量回应用户要求的异常恢复，只改变磁盘提交与重试，保持原可保存阶段、DAT字节、RNG编码、规则、加载后新会话合同不变。任意中途表现的完整检查点不在参考合同内，不伪称已经提供。

采用每槽隐藏事务目录、持久化JSON恢复记录及跨进程排他锁。相比仅逐文件原子替换，这能修复两次替换之间的强杀；相比改变主存档封装，它保留原C++/原存档兼容性。作者自主选择并自审，按用户要求不派发其它Agent、不等待计划审批。

## 磁盘协议

- 同槽`.Save1.DAT.rich4-save/`包含固定锁和至多一份`pending.json`；准备文件只位于该目录。JSON存两份原字节的Base64、各自SHA256及版本，不接受任意目标路径。
- 排他锁内先完成上次已提交事务。新事务先写准备记录、flush/fsync，再原子替换为`pending.json`并同步目录；此替换是提交点。
- 提交前中断保留旧的一对文件；提交点后中断，下一次读取、列槽或写入根据已校验日志完成新的一对文件。两主文件各以同文件系统临时文件原子替换，同步后才移除日志。
- 锁目录保留，避免锁文件删除导致两个进程锁住不同inode。锁等待有界，进程被杀后由OS释放；其它程序不遵守本协议的并发写入不在保证范围内。
- 没有事务目录的外部原DAT读取不创建目录/锁。读前后检查新建事务目录，遇到并发首次写入则重新在锁内读取。坏/缺失可选旁车仍按原合同回退启动种子。
- 无效或损坏的已提交日志明确失败，不覆盖已有主文件；坏档加载仍保留当前会话。只承诺经验证的平台进程中断恢复，不将fsync调用说成已经完成断电/磁盘硬件故障验收。

## 实施与验收

1. 新建`save_transaction.py`和定向测试。先用真实应用保存路径在DAT替换后抛出I/O错误，观察旧实现留下混合DAT/RNG的失败，再接持久化协议。
2. 测试使用合法自然对局产生、已做跨语言比较的`Save1.DAT`与`Autosave.DAT`两对文件。字节与RNG均不同；不构造游戏结果或伪造规则状态。
3. 子进程逐个停在真实fsync/replace/unlink前后，由父进程SIGKILL，再由新进程读取并核对提交点前旧对、提交点后新对。覆盖首次保存与已有槽位、恢复过程再次中断、坏日志、写失败、锁竞争及旁车原回退合同。
4. 接主应用写入/加载和列槽恢复；坏恢复不安装候选会话。补窗口未分类异常的诊断后重新抛出，不吞异常、不跳规则。
5. 串行运行定向、完整Python回归、原应用真实存读档差分、Ruff及实际分发审计；更新恢复说明和函数对应矩阵，隔离集成后合入并推送`dev`。

## 优先审查的边界

- 两文件之间被强杀，下一次读取不得返回混合代际。
- 首次保存尚无主文件时，槽位列表也能恢复已提交日志。
- 恢复时再次中断，日志在两份主文件完整之前不得删除。
- 损坏日志不得借随机种子回退而假装成功；原无日志的可选旁车回退继续保持。
- 原正版文件的普通读取必须只读；隐藏锁的inode不得在正常完成时删除。
