# 玩家间交易

依据固定 `src/trading.cpp`、`include/rich4/trading.hpp` 和 `world.hpp::TradeOffer/OfferKind`，Python 对应 `trading.py` 与原世界出售表。运行时独立使用 Python；C++ 只用于差分。

## 资产与记录

每名玩家七个12字节出售项，种类为股票1、地产2、道具3、卡片4，未知种类和空项保留。股票编号从零，其余从一或原地产编码起。挂牌不预留资产；地产保存当时类型/等级，成交前核对所有权和建筑状态。

列表按股票、普通地产、设施、道具、卡片顺序生成。参考价按原32位回绕和x87截断，挂牌上限为参考价十倍。替换挂牌只修改该种类所需字段，卡/道具保留原数量及地产闲置字节。取消压紧完整记录并清空末项。报价为值快照，不受后来压紧/改价影响。

过期清理保留原 `0x42483e` 行为：首次删除之后删除标志不恢复，其余检查停在压紧后的当前项；遇有效项会停止前进，所以后续失效项可能留待下一次清理。未知和空记录不会被擅自清空。

## 结算与电脑

买方现金支付、卖方银行收款，双方累计收支按32位回绕。地产转移保留租期及建筑；卡片按顺序压紧/追加；正常道具/卡片转移不改变共享供应。私下股票交易先截断旧成本总额，再按新持仓计算binary32成本，重新计算买方公司控制顺序，不改变交易所行情或可购配额。

已核实的异常状态：共享道具供应为255时，卖方归还回绕为零，买方接收因供应为零而失败；原交易代码忽略接收返回，仍结算款项。Python保留此行为并以单测及八图种子1的定向动作核对，不将其静默修成另一套规则。这不是常规新局可预期库存状态；是否需要修正应另做明确兼容性决定。

电脑先清理，再依次消费挂牌 `%15`、改价 `%3`、购买 `%4` 的门控随机数。重复卡候选保留双重循环的出现权重；没有重复卡再考虑过剩/厌恶道具。满表时仅电脑策略可先取消最早项。只购买便宜股票或满足两项严格不等式的地产，不买其他玩家卡/道具；融资对账由后续游戏会话执行。

## 验证

[报告](evidence/trading-differential.json) 覆盖八图三种子共24组、9600动作。定向前缀验证四类资产成交和供应字节边界；其余确定性生成动作覆盖可售列表、限价、挂牌/取消/清理、购买、电脑回合和显式测试持仓变更。逐步比较全部返回值/英文状态文本、公司易主、电脑统计/购买快照、RNG与完整DAT，均一致。测试生成操作 `h` 只设置边界输入，不属于正式游戏。

局部七项测试与完整Python99/99、Ruff通过；尚未实现交易UI、真实回合融资调用和自然游戏长局。当前结果只证明固定C++模块一致，未证明与1998官方EXE完全一致。
