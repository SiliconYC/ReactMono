# 商店与魔法规则

参考固定 `src/services.cpp` 与 `include/rich4/services.hpp`，实现位于 `pygame/src/rich4/services.py`。规则标量和价格来自公开 GPL 源码；本模块未复制商业 UI 文本、图片或声音。图形货架、魔法选择窗口及真实 GameSession 回调尚待接入。

## 商店

- 加权选卡/道具在共享供应非空时恰好消费一次 Watcom 随机数；道具已达九件仍返回抽中的编号，但不扣库存。
- 自有商业建筑先赠品，再进入电脑购物或人类货架。只有控制标志恰为 `1` 才走人类路径。
- 人类货架按临时供应无放回抽取，不提前扣共享供应；购买才转移库存。道具货架直到该型号共享供应耗尽才移除。
- 卡片出售九折向下取整，道具按整笔数量总价九折取整；商店收入的出售部分仍按全价正向累计。关闭商业商店只结算一次。
- 电脑先按原手牌槽位偏好出售，再按卡编号偏好采购，保留源程序的槽位查表行为。购卡按价格稳定降序，同价沿原编号顺序；交通工具预算检查为严格小于，普通道具为小于等于。点券按16位、收入与公司资金按32位回绕。

## 魔法

十二类目标排除控制标志为零的玩家。地产最多包含普通地产与特殊设施；房屋最多计算有建筑的地产个数，而非楼层和。最大值初始为零，财富为零仍可并列，其余数值类零值不进入候选。

电脑反复抽取非空类别；演员也在目标中时固定选择送卡，不再消费效果随机数。其余效果抽取 `%11` 并把 `6` 映射到 `7`，保留原概率和不可选效果。

施法前检查全部目标及必需回调，缺失能力返回失败且不产生部分状态变更。入狱/住院先登记敌意，再处理防御取消或转移；卖道具先把已装备交通工具按字节回绕加回库存，再全价出售。升级/降级/拍卖保留脚下原编码范围，不在服务层重新解释地产或执行缺失事件。

## 验证与边界

[差分报告](evidence/services-differential.json) 记录八图各三种库存/状态条件，共24组、7200个服务动作。每步比较返回值、异常类别、RNG、货架和赠品、回调参数及顺序、完整 DAT 字节。测试钩子仅记录调用，不证明真实命运、监狱、拍卖等会话后果；那些规则须在后续 GameSession 差分中另验。

[首次失败](evidence/services-initial-failure.json) 来自测试准备假定第八图存在普通地产；前七图已一致，随后脚本在设置阶段越界。改为按实际表数量设置测试输入并完整重跑，未改动 C++ 参考或放宽 Python 规则。

```sh
uv run --project pygame python pygame/tools/differential_services.py \
  --source /path/to/pinned-cpp --build /tmp/rich4-cpp-core \
  --map /path/to/map.mkf --report /tmp/services-differential.json
```
