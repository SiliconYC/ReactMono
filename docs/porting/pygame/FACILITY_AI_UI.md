## 实现与依据（2026-10-24，#151）

`facility_picker.py`113物理行对应固定`tools/screens/facility.cpp`117行；`ai_settings_screen.py`174行对应`ai_settings.cpp`138行。两者只构造原界面、编辑或选择，再将真实选项编号/设置交给应用回调，不直接修改世界或生成假事件。

设施条使用原Data517:4/5、五格、缺项暗化、三层黄色选框与悬选名称。第一次点击选中，再次点击或确认提交原选项索引；同决策键保留选择，新键清空。建造设施不能取消，行动目标中只有实际-1选项能取消；按参考保持严格提示及位置/范围路由。画廊专用`Picker::select`不是正式调用路径，未加入Python运行API，映射仍保留该调试辅助未移植状态。

托管设置读取真实`GameSession.ai_settings`，只列人类槽；打开时原值与编辑独立复制，公开查询返回副本。切换标签只切换，同一标签再点才反转托管。卡道具策略两位、三性格、两行比例与全部原按压图/红格保留。拖条最右可取90，箭头才可至100，不能擅自把拖条算法改成百分比满格。取消只关闭，确认按槽0–3顺序仅提交变化设置，随后关闭；完整主应用尚待接线。

原右键取消入口要求存在声音回调：缺失时参考抛`bad_function_call`，Python明确拒绝并抛`ValueError`；正式宿主应始终提供可接收请求的回调，即使静音。已知异常类型差异不伪称一致，正常绘制/声音请求另有下述真实对照。
