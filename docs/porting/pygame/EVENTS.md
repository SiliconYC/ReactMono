# 新闻与命运事件

固定来源`src/events.cpp`、`include/rich4/events.hpp`及原测试，Python对应`events.py`。36个新闻、37张基础命运牌及地图/交通重映射后的49个命运处理编号均已翻译。直接编号入口只执行该处理器，不偷偷替换事件；牌堆入口另行进行准入、跳过和游标推进。

## 牌堆与返回接口

`事件选择_类`保留来源编号、有效编号、下一游标、跳过数。选择本身不更新世界；有效编号0不能当作空值。命运5的准入会看到未活跃玩家的卡片，但实际偷卡跳过未活跃者；交通判定按完整字节，地域事件在阶段非0时排除，前四图分别映射到33–48。

处理器缺候选或必要回调时返回`支持=False`，牌堆入口按固定C++继续推进并尝试下一张，最多整副牌一次。真实选择边界若抛异常，游标赋值尚未发生，保留该牌等待重跑。部分世界变化或随机消费可能已发生；上层仍需原会话的重放/选择机制，不能自行假定事务回滚。

`事件结果_类`保留支持状态、事件编号、消息、地产代码、玩家或股票主体、公司、数值、头像行掩码及四位玩家金额。界面应使用这些真实参数，语音类别在规则阶段确定，不由播放层再次抽随机数。

## 新闻规则

释放/延长以名单前四位为准，不额外过滤玩家活跃状态；计数保留高位语义。原地产候选按普通地再设施顺序复制快照，破坏后仍用原业主/坐标播放表现。连锁建筑降级清空全部连锁层数；设施被没收或降到0时，所有活跃酒店住客统一置到期高位，不额外按酒店位置筛选。

同原编码街道的地价一起调整。七折保留参考的扩展精度截断效果：非零且整十价格比通常整数七折少1，例如100→69；十三成按参考整数规则，并保留16位存储回绕。现金/地产税先向零除再乘；股票税逐持仓积累并每次落binary32，再用软件x87乘`0.05`、转整数及乘物价。所有税额在付款前计算，后续付款导致玩家离场时按原条件提前停止，返回头像金额仍是预先计算值。

股票暂停恢复昨收位并回填原股史游标；新闻走势、公司资金/资金变化和一次/全体更新请求按源码次序。公司翻倍时资金变化加的是翻倍后资金，不是旧资金。新闻36以外编号直接拒绝。

## 命运规则

拆房/征地补偿、身份盗用贷款、银行拒绝、窃取存款/卡片、旅行/消失/监禁/伤病、股票变卖、交通工具损坏、18类金钱得失及全库存变卖均保留原顺序。存款/持仓一成使用原binary32乘数`0x3DCCCCCD`的精确整数乘积截断，不能用十进制除10替代；例如1000000009→100000002。

物理/财运修正分善恶、按阈值0/50/100决定阻止、倍增或随机；即使神明可能阻止，处理器仍先检查源码要求的回调。人类逐受害者选卡，全部右键取消后仍有一次语音随机。保险按原公司类型4查找，找不到会报错，不凭空生成保险方；实际付款、贷款到期、收容、卖股、拍卖、卡片防御与范围破坏留给真实会话实现。

## 固定C++与原官方行为的界限

参考新闻15专门排除「只有已建设施而无已建普通地」的崩溃输入，原处理器会对空普通地产候选除零。牌堆对缺依赖/候选的继续跳过也是固定C++明确实现的容错行为。Python按此固定基准移植并记录，不能据此声称已逐条证明与1998官方EXE一致；不把这些处理改写为伪造的成功事件。
