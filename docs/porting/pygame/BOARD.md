# 原地图场景合成

固定来源 `src/board_renderer.cpp` 与 `board_renderer.hpp`，Python 对应 `board_renderer.py/board_models.py`。地形与投影基础分别见 [TERRAIN.md](TERRAIN.md)、[PROJECTION.md](PROJECTION.md)。商业资源始终只读外部MKF，缓存为本机内存，不公开素材。

## 原行为与接口

`棋盘绘制_类` 按大小写无关查找地图/数据包，解析原五表有符号渲染坐标。`api_绘地面` 按原304项表中首个哨兵前的顺序画地面，再画道路；视口以外的应用栏像素保留。`api_绘制` 接收只读场景快照，先画涨价/查封掩码的RGB555或运算，再按原资源选择人物、特殊人物、物件、地产/设施、公司与景物。

人物帧按朝向减相机旋转分组，动画帧在组内取模；梦游额外绘Data414。特殊人物槽4–8保留睡眠/水上/机器人资源差异。跟随物件按载体后方近/远偏移定位，以该偏移点参与深度排序，并采用反向朝向帧。

业主外观表优先于画面内人物，即使业主住院/离场，地产仍保留其颜色与空地旗帜。产权换色只替换SPR第255槽，透明槽0独立，原资源和各颜色缓存互不污染。地产/设施/景物的编号与资源分支均沿参考实现。

原深度键为 `((屏幕y << 4) & 0xFFF0) | 类别` 后解释为有符号16位。排序稳定，保留人物、特殊人物、物件、地产、设施、公司、景物的入队顺序；同位置活跃人物类别13在普通人物12之后绘制。

## 保持像素一致的优化

扫描行按需分配；纹理逐像素累加延后整数回绕，取样仍只使用原位16–20。固定瓦片内的相机小数对应整数屏幕平移，因此地面以对齐32格的相机和四边64像素余量缓存，最多保留四个中心。只回填视口及实际覆盖的掩码；大画布、异常掩码等走原始路径，保留异常前的部分写入。

RGBA转换用字节查表和批量写入，保留原五位绿色到六位再缩放的值；精灵按非零掩码连续段复制，缓存键包含不可变掩码内容，自拷贝先快照。原始颜色0与`0x8000`的透明键差异仍保留。

[扩展棋盘差分](evidence/board-differential.json)：八图2344例（2328有效、16预期拒绝），包含每图256组瓦片内分数、小视口、宽视口回退及异常掩码。所有RGB555/掩码/计数一致，原272例的哈希与独立基线逐图核对相同。[全65536种颜色](evidence/colors-differential.json) 与 [10000组裁剪/透明/自拷贝](evidence/blit-differential.json) 另行对照固定C++通过；透明alpha由Python契约单测覆盖，C++转换本身不输出透明alpha。完整Python128/128、Ruff通过。

[性能报告](evidence/board-performance.json) 单独测地图0、每模式60帧的CPU合成加RGBA，含源码哈希。固定相机平均13.48ms，小数移动11.25ms；跨瓦片平均43.43ms、p95为325.38ms，首次新中心仍有明显停顿。这里不是实际窗口FPS；尚不满足最终连续移动性能验收，需结合真实移动路线处理预热或进一步优化。

## 冷中心取样缓存（2026-10-24，开发中）

旧性能报告的跨32格相机p95为325.38毫秒；地面中心缓存只帮助同一瓦片内移动，不能消除新中心的扫描成本。本次保留原缓存和原扫描回退，在`ground_samples.py`复用对齐中心后只取决于视口/方向的几何。

两个纹理位面通过原`terrain`扫描器取得每像素的相对瓦片序号和完整10位纹理地址；地址按32位标准数组缓存，不保存固定地图画面。每个新中心仍从实际GND索引找到真实纹理，再用原色表在内存中展开后的颜色取样，背景零索引、覆盖掩码与道路次序保持原值。最多保存四套视口/方向几何；原四中心RGB缓存继续处理小数平移。超限或扫描拒绝仍回到原目标上的原扫描路径，保留拒绝时的画布语义。

先以缺失模块的RED测试确认新取样接口尚无实现，再通过八方向、非均匀纹理、地图边界/负中心、无掩码及含非1旧掩码的17项定向测试。第一版八图2344例（2328有效/16预期拒绝）完整像素/掩码/计数一致；内存颜色展开与空掩码处理后的最终结果见下文。不修改规则、相机投影或使用固定画面替代地图。

同机顺序基线/优化各60帧：跨中心p95从116.027毫秒降至34.109毫秒，平均21.583→10.658毫秒；固定/小数移动平均7.555/7.591毫秒。与较早325.38毫秒报告的负载条件不同，不用它计算本次加速比。全部原始样本、源码哈希和两次CPU指标见 [顺序性能报告](evidence/board-samples-performance.json)。标准预热已包含首次几何准备，因此该报告不覆盖首次视角卡顿；周期性冷中心仍超过16.67毫秒，不能据此宣称完整游戏60FPS或实际设备体验通过。

取样覆盖为几何常量。目标原掩码全零时可以直接使用该覆盖位面；其它掩码逐位保留未覆盖值。新增空掩码定向后共25项取样测试；正式GND/色表与其它资源缓存一样视为只读，不能在外部修改后期待旧缓存自动失效。最终八图棋盘及主应用复验继续留独立证据。

最终版本八图2344例再次全部一致，各图输入/像素掩码摘要与优化前逐图核对相同，见 [完整棋盘](evidence/board-samples-differential.json)。八图实际应用/工具栏/保存读取再次跑1982命令874完整画布，世界DAT/RNG/阶段、像素及实际存档字节一致，见 [应用回归](evidence/application-ground-samples.json)。正式游戏不改变相机或素材；真实窗口FPS、冷视角首次准备与音频同时运行仍保留门槛。
