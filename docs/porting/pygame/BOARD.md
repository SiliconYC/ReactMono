# 原地图场景合成

固定来源 `src/board_renderer.cpp` 与 `board_renderer.hpp`，Python 对应 `board_renderer.py/board_models.py`。地形与投影基础分别见 [TERRAIN.md](TERRAIN.md)、[PROJECTION.md](PROJECTION.md)。商业资源始终只读外部MKF，缓存为本机内存，不公开素材。

## 原行为与接口

`棋盘绘制_类` 按大小写无关查找地图/数据包，解析原五表有符号渲染坐标。`api_绘地面` 按原304项表中首个哨兵前的顺序画地面，再画道路；视口以外的应用栏像素保留。`api_绘制` 接收只读场景快照，先画涨价/查封掩码的RGB555或运算，再按原资源选择人物、特殊人物、物件、地产/设施、公司与景物。

人物帧按朝向减相机旋转分组，动画帧在组内取模；梦游额外绘Data414。特殊人物槽4–8保留睡眠/水上/机器人资源差异。跟随物件按载体后方近/远偏移定位，以该偏移点参与深度排序，并采用反向朝向帧。

业主外观表优先于画面内人物，即使业主住院/离场，地产仍保留其颜色与空地旗帜。产权换色只替换SPR第255槽，透明槽0独立，原资源和各颜色缓存互不污染。地产/设施/景物的编号与资源分支均沿参考实现。

原深度键为 `((屏幕y << 4) & 0xFFF0) | 类别` 后解释为有符号16位。排序稳定，保留人物、特殊人物、物件、地产、设施、公司、景物的入队顺序；同位置活跃人物类别13在普通人物12之后绘制。

## 首批自动证据

[基线报告](evidence/board-baseline-differential.json)：八图、八视角、每图34场景，共272例（264有效场景、8个预期无效旋转）。比较每帧完整640×480 RGB555、可选掩码和地面/道路/精灵计数，全相同。场景覆盖原地图静态、产权/建筑/临时效果、12人物及姿态、全部20物件、特殊人物槽4–8、近/远跟随、分数相机、离图遮挡和独立地面入口。测试场景是验收输入，不进入真实游戏规则。

四项局部测试验证大小写、零号节点、活跃人物遮挡、未绘业主颜色、换色缓存及地面着色；完整Python125/125、Ruff通过。

基线重绘最快约0.13秒，首次资源/姿态加载最长约5.97秒；当前不满足最终交互性能要求。`cProfile` 已定位定点逐像素步进和RGBA转换为主要热点，优化必须继续保持像素差分。这里没有把模块渲染称为图形游戏试玩、流畅动画或完整八图验收。
