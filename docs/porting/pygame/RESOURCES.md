# 资源格式、索引与事件接口

所有条目编号是原文件编号，不重新排序。资源目录由调用者明确传入。现有素材只读，用户原存档不会被预览器修改。

## MKF

`DWORD@0` 定位文件尾索引，每项为资源头偏移。每资源头 16 字节，依次为解码长度、存储长度、图形偏移、图形长度；资源体紧随其后。长度相等表示未压缩。压缩为 321 符号自适应树与距离前缀/6 位后缀的重叠回引用，位序低位优先；根频率 `0x8000` 时通过原更新过程重标度，以保留相同频率排序。单次默认最大解码 256 MiB，越界、截断和提前结束均拒绝。

## SPR / SMP 与画布

头为签名、帧数和数据偏移，随后每帧 12 字节：有符号 16 位宽/高/原点 x/y，再加 32 位数据长度。SPR 数据起始有 512 字节 RGB555 调色板，后续为索引 8 位像素；索引零透明，即使其调色板颜色非零；非零索引的黑色必须可见。SMP 为原 RGB555 字。锚点绘制位置为 `(anchor_x-origin_x, anchor_y-origin_y)`，裁剪右/下边界不包含。

显示须保留 C++ 的 `RGB555 → RGB565` 转换，绿色第六位保持零，再转 8 位，因此最大绿色为 250 而非 255。这是固定 C++ 行为，未独立证明原官方游戏在所有显示模式下均如此。

## FLC

128 字节头，魔数 `0xAF12`；帧块 `0xF1FA`。支持类型 4 调色板、7 增量字游程、13 清零、15 字节游程、16 原始拷贝，按 C++ 忽略缩略图/未知块；索引零透明。`动画_类.api_下一帧()` 修改已有像素与调色板，`api_倒带()` 同时重置两者。全流解码和首尾帧对照已完成，尚未在图形宿主按原时序播放。

## 后续地图与事件契约

原全局地图编号为 `stage*4+map`，0..7。`map.mkf` 的 `2*id` 为 GND，`2*id+1` 为地图表。GND 总览不是原相机投影，不可用总览替代正式游戏。

游戏状态机、决策、事件和特效接口待移植 `game.hpp` 后固定；必须保留 C++ 的有序事件与 `after_events` 演出屏障。当前资源窗口没有伪造事件流，也没有用合成事件代替真实规则。
