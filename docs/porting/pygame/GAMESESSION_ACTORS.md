# 主会话角色与被动防御

`game_actors.py`对应固定`game.cpp:1711..2197`和`instance_position:2691`；资金与回滚复用[金融](GAMESESSION_FINANCE.md)及[事务](GAMESESSION.md)。以下是该组件专项结果，后续公开独立会话自然对照见主会话记录；正式Pygame主UI仍未完成。

## 行为与源码边界

- 附身同步只更新状态所引用的神明/炸弹，不扫描所有带相同玩家号的物件。清缺席保留提早释放的条纹服/病号服，医院优先，并记住原服装输入键。
- 破产人物搬离先清旧占用，原候选按节点顺序抽取，并拒绝任何超过字节的候选；远距离门槛为任一坐标差至少300，最多100000次，不能强行给出近点代替。
- 受伤仅对在场人物收交通工具，完整交通字节非零即重置；仅低位1/2返还对应供应，工程车不按普通车返还。
- 特殊人物4..7收容即不活跃并清状态，天数0仍执行。普通人物首次收容迁移到原出口/景物、同步附身及发影片，已收容则按七位累加；保险、累计倒霉天与公告次序保留。
- 消失首次清缺席/赔偿/累加倒霉天，离场影片显示旧点；延长只改原模式编码，不重复赔偿。
- 免费卡、嫁祸卡与免罪卡使用真实库存/供应及共享随机。免罪自动优先；免费/嫁祸可挂起人类选择，电脑遵循原现金/敌意/随机门槛。嫁祸目标的缺席过滤只用于没有正敌意时的随机后备路径。
- 受害者选卡按手牌首次出现去重。设施拆空释放全部旅馆的活跃住客，工程车拆屋保留业权/租约、记录拆前楼层类型，并增加原敌意。
- 掉头按原邻接/封路位重新选择上次节点。拍卖复用真实`AuctionSession`，人类回答通过原事务重放，保留不合资格掩码、成交赢家与地产；没有固定赢家。
- 物件移除按种类返供应，附身运势按16位减法撤回；前十二神明重生其配对对象，保留原随机流与地面标志清除次序。

## 医院、监狱出生位置（2026-10-25）

原版汇编 `mytbk/rich4/asm/rich4_load_map.asm` 的 `_rich4_load_map` 按节点 `type_and_index` 的 `0x1F41/0x1F42`（8001 医院、8002 监狱）记录建筑节点；`rich4_hospital_utils.asm` / `rich4_prison_utils.asm` 将收容角色置于该节点并保留建筑景物坐标。此前参考 C++ 与 Pygame 误按 `flags & 255 == 5/4` 找到道路事件入口，绕开了建筑至主路的支线。

修复仅调整 Pygame 收容节点选择，以及释放时的旧存档纠偏：当人物仍处于收容释放状态且原节点不属于正确建筑时，按同图建筑编号纠正节点、上一节点和占用标志；其他状态不迁移，已出院/出狱的存档不强制传送。DAT 字节布局、存读接口及地图连接均不改变；未找到建筑时旧存档保持原位置。回归测试覆盖两类收容、新旧节点与存档字节往返；真实八地图与实机试玩需另行验收。
