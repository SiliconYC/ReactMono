# 原道具电脑策略与选择缓冲

固定来源`src/tools_ai.cpp`、`include/rich4/tools_ai.hpp`，Python对应`tools_ai.py`。十三道具逐项判断与UI访问入口均移植；时光机的原谓词始终不选择，库存遍历也排除它。实际使用仍由`tools.py`负责，策略本身不消耗道具或改世界。

## 原访问与随机数

入口要求控制标志包含`6`位且卡片策略包含`2`位。持有种类超过四种才随机起点，最多四次尝试；不足四种也会循环重复尝试。攻击性减救援策略达到2直接拒绝，等于1才抽三分之一门控。不得额外加概率或提前过滤来改变随机数序列。

前瞻最多八步，单路不抽随机，分岔才抽，即使分岔导致后续拒绝也保留消费。这与特殊角色移动的单路抽样不同。路障先前瞻四步找购地/点券机会，再回退到反向六步放置；拒绝第一阶段不等于直接退出。机器人工具、遥控骰、传送、机器工人、飞弹与核弹均保留原顺序、阈值、符号回绕和并列处理。

## 投影与覆盖顺序

原选择缓冲为440×440，使用已差分的原查表投影，相机旋转只取低三位，纵坐标减40。此处是覆盖写入，并非渲染实例缓冲的按位或；后插入同像素的地产/设施可以遮掉角色或前一地产，代码0清掉像素。扫描按行再列，半径区域两端半开，负半径表示全图，0为空。

Python稀疏保存非零像素，并按像素下标排序扫描；没有改变覆盖、裁切或扫描顺序。私有探针限制半径至220，避免原C++超出缓冲的未定义行为；不宣称原函数已有此检查。

飞弹优先有符号正敌意，回退才在活跃且未收容的玩家中抽样；最高敌意目标不先过滤收容。附近实例保留复合编码。核弹十次候选抽样、原单精度阈值和无序比较保留；被后插入零层地产覆盖时可能出现`0/0`，原NaN比较允许通过，不能擅自改成安全拒绝。

## 原寄存器残值的证据边界

固定C++的`ownership_carry`显式承接原`0x409b18`留下的EDX残值，原生参考默认0；尚没有完整原EXE运行捕获证明所有场景必为0。Python保留同一回调，测试输入覆盖0、1、`0xffffffff`。飞弹在整个范围扫描保留该值，核弹只在首个地产判断后清零。这里验证的是固定C++及显式输入，不能声称已经证明1998年官方版的全部寄存器状态。
