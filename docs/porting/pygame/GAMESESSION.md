# 主会话移植增量

实施顺序见 [计划](GAMESESSION_PLAN.md)，固定来源`src/game.cpp`4176行及`include/rich4/game.hpp`。本文件持续区分会话内部组件与真正可玩主游戏。

## 当前：数据、事务和表现分发

`game_types.py`建立原六阶段、二十一决策、十三事件/公告、三语句表、三十三效果编号，以及全部决策/转盘/小游戏/托管/事件/月报/移动/效果数据字段。数据模型并不等于已实现这些规则；月结/转盘等嵌套字段仍需后续真实触发验证。

`game_transactions.py`移植原`run_rule/drop_replayed`。仅保存源指定的世界、RNG、卡片电脑记忆、队列长度和旧阶段；不擅自把整个会话做快照。等待选择时回滚规则，保存已展示事件/效果与续执行闭包；回答后带答案重放，只扣一次款、抽一次规则随机。

表现去重要求旧序列完整匹配，部分匹配不删除，避免吞掉新事件。效果比较忽略相对事件位，删除事件后按严格小于关系修正交错位置。普通异常原样传播，保留源的部分变更，不捕获后伪装成功。不支持异常仅用于固定源确有的缺依赖分支，不可作为未移植规则的跳过入口。

`game_presentation.py`移植原事件/效果/服装/卡图/公告/语句与阶段结束逻辑。事件语音与卡/道具气泡的缺席过滤不同；金额和缺席语音的中间门槛仍会消费共享随机数，不能误当作纯绘制而移到另一个流。地产落点有八tick原停留。购地后神明/工程车分支已经按源接线，但需要后续完整会话提供真实回调，尚未作为完整结算验收。

## 针对性验证

十六项局部测试先见缺模块失败：嵌套两次选择、资金/RNG/记忆回滚、表现保留/去重/交错、部分匹配和普通异常、收容/服装、语音门槛、卡图按值、免租次序、八tick与原不支持提示。完整Python258/258、Ruff通过。

```sh
uv run --project pygame python pygame/tools/differential_game_transactions.py \
  --source /path/to/pinned-cpp --build /tmp/rich4-cpp-core \
  --assets /path/to/Rich4 --report /tmp/game-transactions-differential.json
```

测试适配器直接包含固定`game.cpp`，只在测试编译使用`-fno-access-control`访问真实`GameSession::Impl`；参考源码未修改。Python探针只提供真实世界、状态和同样的显式动作回调，不作为主游戏运行后端。正式运行不加载C++。

[八图三种子报告](evidence/game-transactions-differential.json) 18648命令：2458次显式事务动作、3667次选择回复、1818次恢复测试状态，其余为表现方法/字段/随机准备。每步完整DAT、RNG、阶段/时钟、持续参数/选择记录、决策、事件/效果和服装/返回值一致，385值域/675索引或数值范围拒绝也一致。

回调中的明确资金/事件操作仅用于验证事务机制，不是假装游戏事件，也不计为真实购买、自然回合或长局。探针没有覆盖购地后完整神明/工程车、所有卡图/物件目标，以及月报/转盘等非空嵌套对象；完整会话差分会补齐。
