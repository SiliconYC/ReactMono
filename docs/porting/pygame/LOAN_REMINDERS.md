# 贷款主动提醒修复

## 设计与范围

`game_finance.py::_收到期贷款` 已在回合缺席检查前收款及生成第 3～1 天提示，但 `message_rules.py` 丢弃普通文本事件。保留固定 C++ 的结算、事件顺序、随机数和存档格式，仅扩展 Python 呈现层。

- 第 15、7 天从已有回合开始事件生成提醒；第 3～1 天展示已有贷款提示，第 2 天继续保留原规则预警。
- 弹窗列出玩家、金额、到期日、剩余天数、现金与存款；距到期不超过 7 天且可用资金不足时标明缺口和破产风险。点击或按键后继续，正式模式不自动消失。
- 读档当天按回合开始事件补显临期提醒；与原预警按玩家、当前日期和到期日去重。重新载入会话时清空呈现去重记录，存档不增加字段。
- 主棋盘所有视图常驻显示各人类玩家的欠款和天数，覆盖托管、住院、监狱等状态；还清或破产后移除。异常日期明确显示异常，不猜测到期时间。
- 到期收款事件显示到期贷款额与结算后资金；破产时明确为应还额，避免把未收足的债务写成已足额收回。不增加提前还款入口，不改变银行业务规则。

## 实施计划

1. 为事件映射、资金风险、确认门控和只读常驻显示编写失败回归测试。
2. 添加只读贷款信息组件，接入消息规则、消息层和主屏；运行针对性测试。
3. 使用真实应用与素材，注入临近到期的测试局面，回放提醒、缺席、收款及还清流程，保存实际画布截图；测试数据只写忽略目录。
4. 运行 Pygame 测试集、静态检查与构建，更新源码映射和验收记录，在隔离集成工作树验证后合入并推送 `dev`。

## 验收记录

已完成六种局面的真实应用画布回放：第 15 天资金足够、第 7 天资金缺口、第 3 天住院、第 1 天入狱、到期扣款成功、到期资金不足真实破产。使用正常呈现模式、虚拟时钟和 `Pygame` 输入，确认等待 60 秒不消失且规则世界和随机数不变；确认后关闭，三个主屏视图均保留摘要；真实还款后摘要移除。第 7、3、1 天测试局面另经实际应用读档验证，载入当天重新弹出提醒。截图和详细报告生成于本机忽略目录 `pygame/.local/loan-reminders/`，交付图另存本机会话产物目录，不提交商业素材。测试局面注入不等同于自然长局、操作系统桌面交互或真人试玩。

复现命令：

```sh
uv run --project pygame python pygame/tools/replay_loan_reminders.py \
  --assets pygame/assets --font pygame/assets/fonts/ui.ttc \
  --output pygame/.local/loan-reminders
```

全量回归发现既有测试 `test_回合先刷新股票再收贷款并进入人类待命` 的 `移动样本_类` 缺少 `捕获轮次起点` 字段；在未修改的 `dev` 复现相同异常后，仅补齐测试夹具默认值，不改变核心会话。

独立审查发现电脑到期结算也可能等待真人确认；已通过会话安装时保存人类槽位修复，确保电脑的正常收款和破产均不弹确认，人类破产后控制标志归零仍保留结算反馈。五项回归先失败后通过。

最终验证：`pytest pygame/tests -q` 为 **691 通过，10 跳过**，包含真实素材主应用和既有自然存档恢复测试；跳过项为未提供原始素材对照或音频设备条件的测试。`ruff check pygame`、`uv build --project pygame` 及分发白名单审计通过，产物仅含源码和项目元数据，未收集素材或截图。新增贷款专项回归共 44 项。公开元数据见 [验收记录](evidence/loan-reminders.json)。
