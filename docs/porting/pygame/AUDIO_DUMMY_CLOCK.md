# Dummy音频时钟判据与回调开销

## 实际失败与归因边界

存档回归首次运行633项通过、1项音频探针失败：一秒主线程不供料期间推进36864帧，低于原探针的38400帧判据。普通优先级单独运行也观察到37888帧，故不能把原因只归结为`nice 10`。本轮没有发现或修正PCM/MIDI数值差异。

SDL2 2.28.4的[dummy实现](https://github.com/libsdl-org/SDL/blob/release-2.28.4/src/audio/dummy/SDL_dummyaudio.c)没有真实输出时钟；[公共音频线程](https://github.com/libsdl-org/SDL/blob/release-2.28.4/src/audio/SDL_audio.c#L659-L690)先调用应用回调，再按缓冲帧数整数计算并等待。软件等待和回调工作叠加，不能把其墙钟吞吐直接等同于硬件持续出声的时钟。原探针把不足80%直接描述为“未持续推进”，证据不足；这不是正式游戏规则或采样输出错误。

## 更正后的验收范围

- 原80%数值没有改成更低门槛。dummy报告保留`dummy_nominal_rate_80_percent_pass`和原始帧数/实际观察秒数；它失败时不再冒充“回调未运行”。
- 功能检查改为主线程不调用音频更新的四个连续观察窗，每窗都必须实际推进；仍核查真实声音、语音、回调块数、捕获长度和PCM16格式。
- 真实硬件继续强制80%推进；`real_time_budget_pass`及全部超时/饥饿统计独立保留。功能通过不表示性能通过，更不表示完成硬件长压或人类听感验收。
- 新反向用例在实际游戏PCM/MIDI回调中插入20毫秒调度延迟，不替换采样/规则。修复前误报为“不持续推进”；修复后必须有连续进展，同时dummy名义吞吐和真实回调预算两个标志都为失败，确保慢回调没有被涂成性能通过。

这是纠正开发探针的判断对象，确实改变了dummy的功能判据；并非新增真机通过证据。此前用户对BGM/音效/语音和耳机热插拔的实际反馈继续单独记载。

## 独立的混音统计优化

性能剖析显示每采样峰值统计反复写对象属性并调用`max`。现在仅在局部变量累积，整块结束后回填；FMA、限幅、声道顺序、播放队列及采样本身不变。同进程七组配对、相同300个真实MIDI块：中位数99.687→73.925毫秒，全部PCM字节和完整统计相同，见 [配对测量](evidence/audio-statistics-performance.json)。这不是窗口CPU或硬件延迟的测量。

修改后重新运行固定C++的完整PCM对照：3881命令、4400128个F32采样及私有统计/日志全部一致，见 [完整PCM差分](evidence/pcm-statistics-differential.json)。没有降低任何音频数值比较精度或跳过真实源声音。

本轮全部音频探针使用dummy虚拟输出，只复制游戏自身产生的PCM，不使用麦克风或系统声音录制，也未重新启动桌面采集。重型工作串行，程序内性能测量完成即退出。
