# 原顺序表现队列

## 实现与应用契约（2026-10-24，#148）

`presentation_queue.py`114物理行，实现固定原前端的`after_events`交错、顺序泵、显示回合/破产音乐标志、80毫秒暂停及核心可推进门控。实际消息/电影/骰子/转盘/月报/拍卖/施法等忙碌状态由必须绑定的`呈现宿主_类`提供；该模块没有默认空屏幕，也尚不是正式Application。

先提取效果，再提取事件，按当前效果头的`after_events <= event_index`把效果穿插在事件之前，最后处理批尾；保持原头部顺序，不能排序。按值保存输出、在观察时通知宿主，再在观察末尾立即泵队列。自审补回了最后一步，避免把新暂停的消费时点推迟一帧。

泵一次处理当前头项，直到宿主忙碌或暂停开始：

- 暂停等于`object_kind*80`游戏毫秒，跟随速度设置。只有托管开发重放且关闭效果的原组合会略过；正式游戏不略过。
- 金额转盘/轮盘必须同时有`spinner`数据才交专属屏幕；股利/开奖/月报必须同时有`monthly`数据才交月报屏幕。缺数据仍依原转交EffectPlayer，不能制造固定结果。
- 其它电影交真实EffectPlayer并携带会话所有者；实际播放器自行按原规格忽略专属或无片项。
- 事件按原顺序交宿主，回合开始更新呈现玩家，玩家破产及破产电影置破产音乐标志。宿主仍须完成原MainScreen、消息、拍卖/施法与音频行为。
- 队列为空且所有真实表现空闲才允许主循环推进核心。等待人类转盘决策本身不能被笼统当作阻塞：原核心还要推进交互转盘数位，专属屏幕的`active()`仅指已结算效果播放。

正式主循环尚须接好两次观察、等待扣减、条件骰子递进、旧板面记忆、核心tick及实际draw/消息退休顺序。这里不单独推进核心或回答任何决策。
