# 特殊移动角色

固定来源 `src/special_actors.cpp`、`include/rich4/special_actors.hpp` 与其原测试。Python对应 `special_actors.py`；使用已有世界、库存、软件x87及随机流。槽4–7的规则与槽8机器人分开，不能把此模块视为机器人已经完成。

## 原规则与顺序

活跃角色自己的回合才老化睡眠、梦游、停留和龟行。计数1变为`0x80`，本回合仍生效；下次已有高位则整体清零。正常步数是一次原随机数取余9加2；龟行固定一步但仍按实际路线抽随机数。

单步按原四邻居顺序，排除来路和方向禁行位。有前进候选时即使只剩一条也抽一次随机数；没有候选则无随机返回来路。占用位按槽转移，方向与坐标到达真实端点；像素插值属于后续表现层。普通玩家的`current_player`保持不变。

交互在调用任何外部回调前复制节点标志及类型，之后即使移除物件改写节点也沿用原快照。狗的移除参数固定11，赠品/点券固定13/14，其余按物件编号。槽4经过可拾取障碍/雷/炸弹而非停步；其它槽经过路障即停止，踩雷需停靠。拾取仍可能因道具达到9个或供应耗尽失败，但相应原效果和移除顺序不会被改写。

槽4拿最低槽位其它占用者的一半点券；该最低占用者未活跃时不继续找别人。槽5先随机偷卡，再在银行事件按软件x87的`0.2`逐玩家请求付款。槽6停靠征收同业主同原编码街名的地价总和或设施地价乘物价；槽7按已移除建筑字段，或公司完整资金和原公司付款人编码征收。累加/乘法保留32位回绕，最终以有符号金额传给真实融资回调，不能按现代常识钳到零。

监狱/医院目标首次经过只置高位，再次经过才返回，并调用特殊角色收容接口。游戏结束检查在每个移动步前；交互效果先合并，步后回调随后发生，再检查缺失规则/停止/不活跃状态。

## 接口与不完整边界

`特殊回调_类`提供付款、物件移除/归还/再生、特殊角色监狱/医院、语音、游戏结束和步后表现。必须接入真实GameSession；当前差分中的钩子只观察参数并注入明确的测试状态变化，不实施或假装完整融资、破产、再生或声音。

缺失必要回调按C++返回`支持=False`。这个拒绝不保证事务回滚：例如槽5先偷卡，随后缺银行回调会返回一个全新的失败结果，先前效果清单丢弃但世界中的卡已转移。上层必须按原顺序准备依赖并处理失败，不得看到空效果就假定世界未改变。

