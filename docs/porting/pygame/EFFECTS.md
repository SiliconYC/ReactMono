# 板面场景与电影表现

## 场景/规格基础（2026-10-24，#148）

`effect_scene.py`和`effect_spec.py`共312物理行，对应固定`tools/screens/effects.cpp`前九个场景/电影规格函数。`board_models.py::场景_类`直接拥有精灵列表，承担原`SceneData`及其`view()`；没有引入C++运行后端。

这一步只完成静止快照、人物/物件显示判定、电影规格和待播演员覆盖。`EffectPlayer`逐帧播放器、正式应用表现队列及移动中的主板面构造仍待实现；不能将规格一致当作电影像素一致。

## 规则已结算，画面尚未提交

核心在输出`EffectEvent`前通常已经修改世界。例如玩家已进入医院，但救护车尚未播放。前端必须用旧位置和快照显示电影提交帧之前的画面，并暂停核心时钟，才能保留源表现顺序。这里的接口不倒改规则世界，而是构建独立的场景值：

- `api_在棋盘()`按实际控制字节和收容状态判断，允许仅`y`非零；原`0x20`位会覆盖全部离场状态判断，未按注释擅自缩窄为酒店。
- `api_静止快照()`生成人物/服装、附身或站立物件、地产/设施/公司/业主、特殊人物。帧序为原`uint64(ticks)/120%6`。
- 附身物件使用已经绘制的人物坐标/方向；载体隐藏时不画，带神明的定时炸弹沿用远跟随值2。
- `api_加入待播()`由首个涉及同一玩家的电影决定旧位置/隐藏/受伤；`api_应用待播()`复制已有精灵或从真实世界补建，避免提前把人物移走。`None`和坐标`(0,0)`语义分开。
- `api_隐藏物件()`仅调用未附身项的隐藏谓词；正式应用还须把尚未落地的抛物交给该接口，不能在空中提前出现道路物件。
- `api_查询()`保留全部33类效果的资源号、提交帧、音效/声音帧、停留毫秒、相机锚点、演员覆盖和神明末帧保留。转盘/月报/骰子等仍由其原专属屏幕负责。
