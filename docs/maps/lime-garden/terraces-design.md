# 青柠游园联排经营设计与实施计划

2026-10-22。所有者要求只升级 `lime-garden-30`；不改变其他地图的布局与经营规则。设计与实施由本次授权覆盖。

## 证据与选择

旧 `rowHouses()` 只识别连续已建住宅，`upgradeProperty()` 和 `rollTurn()` 仍逐格升级、收租；青柠专用模型没有连接体。采用显式街区及同主连续分段，避免把曲线路径的空间近邻误认为可联排土地。

仓库 `docs/research/repositories/mytbk--rich4/source-index.md` 的 R07/R08（B 级静态源码证据）记载按所有者、街区、等级累计通行费；没有已验证的统一建造与混级算例。因此只借鉴累计思想，不复制上游代码、原作资源或未经验证的固定基数。

## 规则

- 固定街区：`[1,2,3]`、`[5,6,7]`、`[9,10,11]`、`[13,14,15]`、`[17,18,19]`、`[21,22,23]`、`[25,26,27]`、`[29]`。编号为内部零基 ID。每格土地为相邻等边正方形；街区之间留绿地，地砖紧邻对应地产。
- 同组按顺序相邻、同一业主且未抵押的土地组成一排；空地参与。未购地、其他业主、抵押及街区边界截断。出售、清算、破产及解除抵押后实时重算，不另存成员副本。
- 到访任一成员，允许一次整排升级。仅最低等级成员升一级；高等级保持原状。例：`[2,0,0] → [2,1,1] → [2,2,2]`。本作既有等级为土地 `0`、住宅 `1`、高级住宅 `2`，不凭空加入第三级。
- 费用为实际升级成员各自下一层费用之和；一次原子扣款，资金不足完全拒绝；每次停留仍仅一次购买或建设。每个真实升级成员产生独立事件，供账本和动画复用。
- 对手落在任一成员，支付整排各自当前等级租金之和；不再叠加额外倍数。三块基础地价 `120` 的最高级街区收费 `288`，建设成本合计 `468`，购地成本 `360`。混级如 `[2,0,0]` 收 `144`。每块抵押地自身免租且截断。
- 真人、电脑、后台模拟、风险报价和资产详情共用纯函数报价；免租覆盖整笔，存款、股票和清算沿用现有真实账本。
- 新青柠对局保存可选 `terraceRulesVersion:1`；其他地图不能启用。没有此字段的历史对局保持原规则，无损往返，不在加载时悄悄改约定。

## 实施步骤

**目标**：在真实游戏中建立可购买、可建设、可收费且视觉连续的街区。

**架构**：纯规则模块 `src/core/property-groups.ts` 定义街区、产权分段、升级和租金报价；核心交易调用报价。专用青柠模型与地图数据处理空间和建筑连接，UI 展示同一报价。

**技术**：现有 TypeScript、React、Three.js、Node 测试及真实 Chromium；不增加运行时依赖。
