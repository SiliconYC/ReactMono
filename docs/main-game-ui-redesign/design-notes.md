# 设计解读与讨论补充

本文件把聊天中的重要判断和视觉语义显式保存下来，补充完整方案；不是新增游戏功能清单，也不是逐字聊天记录。

## 所有者的原始意图

主程序4174界面混乱，按钮、菜单、文字配色缺乏秩序，开始界面像网页附加表单；买地重播骰子、镜头跟随突变等操作问题破坏信任。参考4173 demo的整洁与流畅，允许正式游戏更复杂，但每个元素必须有意义。任务最初明确只要求详细方案，不改游戏。

随后所有者认可原方案和四状态示例，指出单一Markdown难以保留视觉信息，也担心有价值的对话结论遗漏。此次明确要求：改用一个目录保存完整建议、保留网页示例、使后来阅读者不用聊天上下文也能理解；复杂内容落盘，回复简短。

## 不能在后续迭代中丢失的判断

1. 采用“保留现有规则/AI/存档/3D世界，重建页面、HUD和演出协调”的路线。继续给旧侧栏加折叠无法解决职责拥挤；整个游戏换技术栈则代价和回归风险过大。
2. demo值得学习的是棋盘为主体、信息稳定集中、当前操作唯一、金融窗口独立、因果顺序清楚；不是机械复制demo的尺寸与两人局假设。
3. “像商业游戏”不等于加特效或豪华装饰。玩家应始终知道谁在行动、现在发生什么、下一步做什么；复杂度通过层级处理，不能变成更多常驻方框。
4. “买地又掷骰子”的本次核查是旧骰点动画重播；该次购买没有新增投骰事件、没有改变随机状态或位置。但这会让玩家怀疑操作，不能以“只是表现”降低修复优先级。
5. 镜头和输入不能各自用猜测的计时器协调。当前旧计时器比3D演出短，按钮又提前显示；正确性和视觉重排必须一起推进。
6. 看起来可以操作、按下才提示“请等候”是错误的界面契约。双击第二下也不能落到刚替换的新按钮，意外完成另一项操作。
7. 标题页、准备页、对局HUD要真正分离，不能把一个运行中的行动面板搬到左边，再隐藏几段文字冒充开始界面。
8. 到访自有地产直接展示建设决策，不让玩家钻进金融→地产的长列表找升级。每次到访一次操作、购买/建房/升级分次进行的规则保持。
9. 不要把“无效按钮全部灰掉”当成信息架构。无关内容可以不出现；值得查看但暂不能执行的内容要准确说明开放时机。
10. 世界反馈、HUD数字与输入阶段要一致。动画可以延后揭示已提交结果，不能再执行规则，也不能让AI在观众看完前连续走到下一阶段。
11. 交易需要清楚展示账户、成本、手续费与后果；不把重要交易简化成无说明的图标，也不让每笔普通操作都被重复确认打断。
12. 原生按钮/输入/选择器保留语义和键盘能力，游戏化的是视觉与空间组织。不能为了不像表单而制作不可访问的假控件。
13. 图文示例是设计工具；不能用“看着像完成了”、漂亮截图或单元测试通过，替代真实完整游戏验收。

## 四状态示例应该怎样读

### 标题画面

看游戏标题、主菜单与小镇构图的关系；有存档时“继续游戏”为主，无存档时应改为“开始游戏”。这里故意没有地图表单、回合资产、金融、选地块或开发诊断。

示意采用左侧主菜单只是本轮构图建议；关键是明确游戏身份和开始/继续流程，并非“只要菜单在左边就算符合设计”。

### 新局准备

看地图卡、玩家席位与固定开始操作的关系。正式实现要支持2～4人、姓名修改、真人/电脑、已有电脑策略、规则设置和错误提示。示例只展示两席，不意味着删除四人局或已有配置能力。

### 等待掷骰

看左上稳定玩家条、顶部轮次、右上镜头/菜单、底部唯一主要操作。当前行动者和钱的位置不随事件变动；手牌不再列出所有零库存卡牌。

### 到访购地

看行动区如何从“掷骰”切换为“地价/租金/购买后余额+两项选择”。这是一个新的决策阶段，真实实现必须等骰子/行走结束才开放。

购买示例中的110/22/1390来自默认流程的样例；其他姓名、轮次、现金和卡牌是布局内容，不是实时数据。示例点击“购买”或“暂不购买”会打开解释性反馈，不能据此推断程序已购买、换人或完成回合。

## 示例能力和局限

| 示例中可观察的内容 | 不能据此推断的实现 |
| --- | --- |
| 四状态切换、返回/开始等页面导航 | 真实GameState、完整游戏路由与存档恢复 |
| 资产/银行/股票/手牌/设置等面板切换 | 真正的资金交易、卡牌使用或设置保存 |
| 地图卡的选中态 | 地图模型、规则或价格配置实际切换 |
| 全景/跟随按钮文字切换 | 真实镜头插值、安全框、用户手动浏览 |
| 简化小镇、棋盘、人物标记 | 最终3D美术、光照、阴影、动画或GPU性能 |
| 手机宽度的排版 | 真实手机发热、触摸质量、完整PWA验收 |

正式实现仍需标题/准备/等待投骰/行走/买地/建设/租金/商店/医院监狱/AI/多人交接/交易/结算等完整状态；四个示例不是缩减功能范围的许可。

银行、股票在到访未处理阶段可以查看，但示例明确交易要等合法阶段。菜单展开应互斥且阻挡世界输入；示例只能展示视觉意图，正式游戏还需真实焦点、点击穿透、Esc、取消和旧回调测试。

## 视觉与技术的一致性要求

奶油浅面、墨绿文字与行动底条、金色主操作服务于层级，不是不可调整的品牌定稿。实际色彩、字号和间距以可读性验证；不机械照搬示例中的每个像素。

相机布局必须读取HUD实际占位：四人卡、长名字、底部决策与交易窗口都可能改变安全区。示意棋盘的大小/裁切不是镜头验收规范。

沿用仓库全场景统一投影/受影、正确阴影模式、统一地表高度和薄地砖要求。UI改造不能通过为某些模型关闭阴影或增加悬浮厚度掩盖3D问题。

既有存档、现金/存款分账、每次到访限制和静态离线部署保持；UI偏好应独立于游戏存档。React/Three/R3F升级不是本轮重设计前置条件。
