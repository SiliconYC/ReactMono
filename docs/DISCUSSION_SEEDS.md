## D01｜[路线图] 六阶段开发路线图：每阶段怎样才算完成？

**建议分类**：目标与路线图  
**状态**：待发布｜**对应文档**：[ROADMAP.md](ROADMAP.md)

### 开场帖

本仓库必须同时完成两个任务：做出完整可玩的《大富翁4》风格简体中文游戏；检验 AI 能否围绕总目标持续自主找问题、选择任务、编码和验证。

提出六个阶段（这是能力门槛，不是工期承诺）：

- P0 目标和治理：固定准本地、简中、dev 约束，建立讨论→执行晋升机制。
- P1 第一局能玩到底：地图、掷骰、买地、租金、破产、胜负、基础对手。
- P2 稳定的准本地游戏：土地升级、基础卡片/事件、Pages、PWA 离线、多存档与文件备份。
- P3 丰富核心玩法：股票、银行、更多道具、特殊状态、多地图与更聪明的电脑玩家。
- P4 高完成度：美术、音效、节奏、可用性、性能、稳定性。
- P5 长期自主进化：持续用可复现证据支持迭代，检验不少于 30 轮自主改进。

自主进化实验从 P0 开始，贯穿全部阶段；不允许用自称“AI 工作了很多”替代游戏质量。

**讨论问题**：每阶段是否有明显遗漏的“无法进入下一阶段”的门槛？哪些能力应提前？哪些属于锦上添花而不该成为阻塞项？

**禁止事项**：不以此讨论直接创建一长串 Issue；先明确阶段退出标准，再选择当前阶段少量可执行项。

## D02｜[P1] 首个完整对局的最低玩法边界

**建议分类**：游戏设计  
**状态**：待发布

### 开场帖

第一版重点不是还原每张原版卡片，而是让普通玩家**不使用开发者工具、不靠人手改状态，从开局玩到产生胜负**。

初版候选范围：一张小型封闭路径地图、玩家/基本电脑对手、掷骰与移动、地产购买和收租、初始现金、基础资产结算、破产与胜出、简体中文操作指引。规则引擎必须可以在无页面环境下用固定随机种子测试。

**讨论问题**：
1. 首局最合适的人数和对手组成是什么？至少保证一个人在一台电脑上能完成整局。
2. 地图与经济参数怎样控制到可以快速测试，而不把正式设计限制死？
3. 自动模拟和真实浏览器完成一局，各需要哪些验收证据？

**晋升规则**：只有经讨论确认的最小可交付切片才进入 Issue；不预先把全部未来机制塞进 P1。

## D03｜[技术] 纯 GitHub Pages + PWA + 本地存档的产品边界

**建议分类**：技术与部署  
**状态**：待发布

### 开场帖

已经确定的硬约束：部署到静态 GitHub Pages；浏览器内运行完整游戏；PWA 缓存后可断网玩；IndexedDB 本地保存多存档位与读档、自动保存，支持文件导入导出；不建立账号、不做跨设备自动同步、不依赖游戏服务器；游戏界面**只做简体中文**。

**可讨论的实施问题**：PWA 资源更新与缓存失效策略、`/ReactMono/` 子路径兼容、存档版本与迁移、浏览器清理数据提示、哪些节点自动保存、如何在离线状态下完整测试。

**不在讨论范围内**：云端账号系统、英文版、收费后端、服务端实时逻辑。导出存档用于人工备份和拷贝，不意味着提供云同步。

**晋升规则**：不为未来用户系统/国际化预建基础设施；先把最小离线、存读档闭环做稳。

## D04｜[实验] AI 自主发现改进方向后，怎样才能晋升为 Issue？

**建议分类**：定向进化  
**状态**：待发布

### 开场帖

我们要检验的是 **AI 是否长期让游戏变好**，而不是谁创建的 Issue 更多。

建议链路：
观察缺陷、玩家体验或缺口 → Discussion 中去重、比较、形成假设 → 准入评审 → 少量可验收 Issue → 任务分支和 PR → 独立测试 → 通过则合并 `dev`、失败则修复/回滚 → 结果回写讨论池。

准入条件：对应阶段目标、证据或明确缺口、无重复、玩家收益或工程收益、范围够小、独立验收办法、成本与风险可控。严重且确定的 Bug 可以直接进入 Issue。

建议初期并发 3–5 个、候选执行队列 10–20 个；未晋升方案可以保留、否决或继续研究。验收应衡量真实玩家能力、回归、首次通过率、自主闭环比例和人工干预；不能删除测试来提高通过率。

**讨论问题**：如何防止规划 Agent 无限产生任务？怎样分离实施者与验收者？怎样记录失败教训，避免重复犯错？什么条件触发暂停与人工介入？

**首轮试验**：只批准足以构建 P1 的少量任务，并展示一次完整的讨论→Issue→PR→验收链路。

## D05｜[玩法] 致敬《大富翁4》时，哪些机制必须还原？哪些应该重新设计？

**建议分类**：游戏设计  
**状态**：待发布

### 开场帖

产品目标是重现《大富翁4》带来的回合、地产竞争、卡片与经济博弈的乐趣，不默认取得原作素材版权。角色造型、地图图像、音乐、音效、台词等必须使用原创或有明确授权的资源。

**讨论问题**：
1. 哪些机制是玩家能立刻辨认的核心（例如地产、升级、股票、卡片、随机事件、特殊状态）？
2. 哪些旧设计可以简化、调整节奏，而不伤害经典体验？
3. 如何在 P1 只实现最小闭环时保留未来可扩展性，却避免过早复杂化？

这里是**长期素材与体验讨论**，不是自动生成几十个任务的入口。候选改进经过评审后，才进入与当前阶段相关的 Issue。
