# P4 #67 · 真实行动反馈与轻量逐格行走

本轮仅新增 React 表现层和同源 CSS、浏览器验收，规则引擎/随机种子/存档结构不变。

- `src/ui/feedback.ts` 从成功的 `applyAction` 事件创建中文视觉事件信息（掷骰、收租、买/卖地产、股票、银行、贷款、卡片、医院、破产、终局）。收入/支出以正负号区别，明确来源；不依赖文字推断交易结果。
- 逐格移动完全由地图实际 `map.route` 推导出从原位置到新位置的路径（含路障提前停止）。每 85ms 标记下一格；棋子正式落点由引擎立刻更新，短途动效只是额外踪迹，既不伪造掷骰也不等待动画再结算。CSS 不承载经济逻辑。
- 用户可通过顶部「关闭动效／开启动效」及「跳过动效」控制；系统 `prefers-reduced-motion: reduce` 和现有快速模式下直接省略过场。独立 `localStorage` 键保存关闭偏好，不修改游戏存档；纯静态网站和 PWA 离线均可运行。
- 每次新行动取消前一个视觉定时器；读档、重开、进入后台、卸载组件亦销毁未完成动效。定时器带递增令牌和游戏 revision 比对，过期回调不可能覆盖新的动效或影响真实游戏状态；电脑不依赖视觉动画完成才继续合法行动。
- 屏幕上保留 #66 当前操作、原有最新事件及核心 CTA。动效内容只在棋盘中心简短显示，不添加大型文字覆盖层。实时 React/CSS，无 MP4、GIF、视频替代。

## 自动化证据
- `tests/p4-motion.test.mjs` 验证独立事件派生不改变引擎状态、随机轨迹，检查 PWA 资源缓存。
- `tests/browser_p4_motion_e2e.py` 使用实际 Chromium 桌面/手机检查跳过动画不改变 revision、关闭动画重载后保留、系统降低动效仍可掷骰、无 JS 异常，存截图/机器轨迹。
