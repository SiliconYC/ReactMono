# P4 #66 · 操作优先的桌面与手机界面

## 依据与独立开发边界

继承 #62 `docs/P4_EXPERIENCE_BASELINE.md` 的真实 Chromium 六视口问题清单，#63 纸艺小镇视觉规范，以及 #64/65 双地图、四人原创棋子。

- 只改 **React UI、同源 CSS、浏览器测试与验证记录**，不修改任何 `src/core` 经济、规则、地图、骰点和存档协议。
- 目标是让**棋盘 + 当前操作者 + 最常用行动**占据首屏视觉优先级；银行/股票/贷款/地产交易须用户明确展开一次，关闭上一个交易组，避免同时堆叠。
- 电脑与真人仍分别展示角色、座位和当前资金；已抵押、现有股票、银行存款、净资产不丢弃，只把明细放在摘要之后。

## 具体实现

1. **布局**：桌面大于 1060px 继续采用棋盘左、回合操作右。小屏及平板按**当前行动 → 棋盘 → 存档 → 玩家 → 日志 → 帮助**排列；手机首屏先可直接掷骰、购买地块/结束回合，完全不依赖悬停。棋盘内坐标、缩放、路径与 #64 保持一致。
2. **财务管理**：回合待结束时，主按钮「结束当前回合」始终位于财务入口之前。下方只显示地产、银行、抵押借贷、股票四个工具标签；初始全部收起，点击任一标签只展开该类操作。银行和贷款共用输入值但每次仅显示一个输入框。禁用金额由规则已有资金/持仓/额度条件控制；不借 CSS 允许不可见操作。
3. **可展开信息**：资产总览改为全员轻量摘要（座位、姓名、净资产），用户触碰摘要才展开原六项财务指标；存档、玩家信息、最近事件、帮助仍可通过原生可操作摘要展开/折叠。保存入口及读档功能完整保留，持久化无格式迁移。
4. **风险与保护**：高风险抵押/借款、≥500 的银行大额转账/还款、≥300 的股票交易（或 ≥50 股）、高价地产/升级均经 `window.confirm` 二次确认；拒绝后 `revision` 不变。相同状态重复命令及 350ms 内相同已提交命令被前端抑制；引擎仍是唯一经济状态写入点。异步手动存档写入有互斥保护与状态提示。
5. **无障碍**：触控标签最小 44px，`aria-expanded` 与 `aria-controls` 指示目前哪个工具可用；聚焦样式、高风险取消反馈及原有 `role=status` 保留。移动端纵向主流，不设置整个文档的横向滚动。静态 `site/action-layout.css` 加入 `scripts/build.mjs` 指纹及 `site/sw.js` 精确预缓存，可离线运行。

## 验收证据与旧基线对照

- 旧 #62 原始基线见其 artifact `issue62-experience-baseline`；基线时移动端操作顺序是棋盘/资产和密集交易，原始数据记录 `under44px`、首屏按钮、各矩形与相同 6 个窗口。
- 新版 `tests/browser_p4_action_layout_e2e.py` 采用相同浏览器版本环境和 seed 17，采集 1440×900、1280×800、390×844、320×640、667×375 的实际 DOM 矩形/可见按钮数/首屏分布。明示 `beforeFinance` 与 `finance` 状态、角色席位及资产展开；**旧页面静态基线与新版不同 CI 时间/图片，不能称同机实时 A/B 测试**。
- 浏览器在两个地图及真实身份下直接完成银行存款、股票买入、贷款标签启用、抵押取消及确认、贷款借还、手动存档读取与 PWA 断网展示；失败必须保留截图及日志，不允许降级为模拟。
- 单测 `tests/p4-action-layout.test.mjs` 保证 CSS、React 实际渲染组件、同源缓存；完整保留 P1～P3 旧回归（旧金融 E2E 只补充进入新工具面板所需的一次用户点击，保留原资产断言和交易链路）。CI artifact `issue66-action-layout-chromium` 含原始 `report.json` 及截图。
- **尚无真人玩家可用性反馈**；视觉密度判断属于设计检视，自动化浏览器仅证明可操作、无溢出和交易正确，不声称证明玩家满意度。

Issue 验收及合并以 PR #79 最新 CI、合并后 `dev` CI 和 Pages 完整结果为准。
