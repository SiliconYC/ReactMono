## 治理决策

### 2026-10-15｜G001：讨论载体改为仓库内提案池

- **背景**：原规划让 GitHub Discussions 承担探索讨论，Issue 只负责成熟任务。仓库已启用 Discussions，但当前承担维护工作的 GitHub 连接缺少可靠的创建/修改 Discussion 能力。
- **人类决定**：改用仓库内 Markdown 提案池，保留与 Issue 分层的理念，不要求用户手动维护论坛。
- **实施方式**：[EVOLUTION_POOL.md](EVOLUTION_POOL.md) + `proposals/Pxxx-*.md` + 本日志；只把经过筛选的可执行事项晋升到 GitHub Issue，PR 与验证记录作为执行证据。
- **理由**：读写与历史记录可以使用现有 GitHub 文件操作完成；避免提案停留在不可维护的外部系统。
- **取舍**：放弃论坛式嵌套评论，改用文件变更记录意见与证据。仍可保留 GitHub Discussions 功能，但自主工作流不得依赖它。
- **关联**：[P004](proposals/P004-evolution-governance.md)、[Issue #1](https://github.com/SiliconYC/ReactMono/issues/1)。

## 2026-10-18：demo 全局阴影稳定性

- 来源：所有者反馈地砖阴影太淡，角色阴影重叠或角色/相机移动时出现高频闪烁，并要求所有物件统一受光投影。检查发现 `<Canvas shadows>` 在 R3F 8.18 中映射到 `PCFSoftShadowMap`；当前 Three.js 0.186 已移除该模式并在渲染时回退为 PCF。该 PCF shader 按屏幕像素噪声旋转五点 Vogel 采样，移动接收面时会让软阴影边界变化。
- 修复：全局改用受支持的 VSM 阴影映射，阴影图 1536 提高到 2048，阴影相机深度范围从 0.5–36 收至 10–28，统一强度从 0.3 提到 0.58，normal bias 从 0.025 降至 0.012。没有为任何物件单独更改 cast/receive 设置。
- 验证：`npm run demo:build` 成功，`git diff --check` 通过；本地 Chrome 检查地砖、灯柱和相邻角色的静态阴影，并在投骰角色移动/跟随镜头时连续观察，之前 PCFSoft 回退警告不再出现，地砖接收阴影更清晰、未观察到原有边缘闪烁。手工短时浏览器观察不等于长时或所有 GPU 兼容性验证；远程 CI/`dev` 集成结果后续记录。
